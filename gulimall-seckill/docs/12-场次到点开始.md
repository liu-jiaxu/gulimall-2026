# 业务流程 12：场次到点开始

## 一、设计思路

- 用延时 MQ 驱动 `seckill_state` 从 `0 未开始` 变为 `1 进行中`，避免轮询数据库。
- 场次保存与本地消息表 `mq_message` 在同一事务落库，事务提交后才投递，避免“场次没保存但消息已发出”。
- 消息体携带 `startTimeMillis`；修改场次时间后，旧消息因与数据库 `start_time` 不一致被忽略，由新消息生效。
- `markRunning` 使用条件更新，条件包含 `status=1`、`seckill_state IN (0,1)`、`start_time <= NOW()`、`end_time > NOW()`，保证重复投递和并发停止都幂等。
- 消息早到时重投一条到真实开始时间；消息晚到且已过结束时间时忽略，交给结束结算流程。
- 状态为 `2 停止中`、`3 已结束`、`4 已取消` 时直接返回，不覆盖人工状态。
- 消费失败按 10 秒、30 秒、60 秒延迟重试，3 次后进入死信队列归档。
- 只改数据库状态，不读写 Redis、ware 库存和订单；抢购判断依据是商品 Hash 中的开始和结束时间。

## 二、主要功能描述

**触发动作**

- 管理员在后台新增场次，或修改一个有效状态仍为未开始的场次。
- 保存成功后，coupon 在业务事务内登记开始消息，事务提交后投递到 RabbitMQ 延时交换机。

**前置条件**

- 场次已存在且 `status = 1`；`seckill_state` 不是停止中、已结束或已取消。
- `start_time`、`end_time` 均非空，且 `end_time > start_time`。
- RabbitMQ 已启用延时消息插件，coupon 的 `mq_message` 表可写。

**状态定义**

- 存储状态取值为 `0 未开始`、`1 进行中`、`2 停止中`、`3 已结束`、`4 已取消`。
- 只有 0 和 1 能被 `markRunning` 改为 1；2/3/4 属于人工或结算终态，不被开始消息覆盖。
- 有效状态由存储状态与开始、结束时间共同计算，人工终态优先。
- 页面展示使用有效状态，数据库 `seckill_state` 才是消息是否消费成功的依据。

**做什么**

- 新增场次时强制 `seckill_state = 0`、`status = 1`，保存后预约开始和结束两条延时消息。
- 修改场次时保留原状态、启用标记和创建时间，重新预约开始和结束消息。
- 消息到期后由 `SeckillSessionStartListener` 消费，调用 `markRunning` 把状态改为进行中。
- 旧消息、早到消息、晚到消息、重复消息都在 `markRunning` 内处理。

**不做什么**

- 不创建或修改 `seckill:stock:*`，不重建商品 Hash。
- 不修改 `wms_ware_sku`，不锁库存、不释放库存。
- 不创建订单、不发送建单消息。
- 不主动结束场次，结束由 `seckill.end` 消息和结算流程处理。

**结果状态**

| 情况 | 数据库状态 | 后续 |
|---|---|---|
| 正常到点 | `seckill_state: 0 → 1` | 记录开始日志 |
| 重复消息 | 保持 1 | 条件更新可重复执行 |
| 旧消息 | 不变 | 开始时间与数据库不一致 |
| 消息早到 | 不变 | 重投到真实开始时间 |
| 已过结束时间 | 不变 | 交给结束结算流程 |
| 场次不存在、下架或人工终态 | 不变 | 不报错，消息签收 |

## 三、执行顺序

1. `SeckillSessionController#save`：接收场次表单，调用 `saveSession`。
2. `SeckillSessionServiceImpl#saveSession`：校验开始和结束时间，强制 `seckill_state=0`、`status=1`，写 `sms_seckill_session`。
3. `SeckillSessionServiceImpl#sendStartMessage`：`status=1` 且开始时间非空时计算 `delay = max(0, start_time - now)`，调用 `sendReliable`。
4. `SeckillSessionServiceImpl#sendEndMessage`：同一次保存还预约 `seckill.end` 消息，由结束结算流程消费。
5. `MqMessageServiceImpl#sendReliable`：序列化消息，向 `mq_message` 写 `message_status=0`、`delay_millis` 和路由信息。
6. `MqMessageServiceImpl#afterCommit`：事务提交后调用 `doSend`；延时大于 0 时使用延时模板并设置 `x-delay`，投递失败保留记录等待补偿。
7. `SeckillSessionController#update`：接收修改表单，调用 `updateSession`。
8. `SeckillSessionServiceImpl#updateSession`：只允许有效状态未开始；时间缺省用旧值，状态、`status`、创建时间强制保留旧值。
9. `SeckillSessionServiceImpl#updateSession`：调用 `validateTime` 和场次时间重叠校验，`updateById` 后重新发送开始与结束消息。
10. RabbitMQ：延时到期后按 `seckill.start` 路由到 `gulimall-seckill-start-queue`。
11. `SeckillSessionStartListener#onStart`：反序列化 `sessionId` 和 `startTimeMillis`，调用 `markRunning`，成功后 `basicAck`。
12. `SeckillSessionServiceImpl#markRunning`：场次不存在、未启用、状态为 2/3/4 或时间不完整时直接返回。
13. `markRunning`：`startTimeMillis` 与数据库 `start_time` 不一致时判定为旧消息并返回。
14. `markRunning`：当前时间早于开始时间时，重新投递一条到真实开始时间并返回。
15. `markRunning`：当前时间已到或超过结束时间时返回，交给结束结算流程。
16. `markRunning`：条件更新 `seckill_state=1`，条件包含 `status=1`、状态 `IN (0,1)`、`start_time <= NOW()`、`end_time > NOW()`。
17. `SeckillSessionStartListener#onStart`：解析失败或数据库异常时调用 `MqRetryService#handleFailure`。
18. `MqRetryServiceImpl#handleFailure`：重试次数小于 3 时按 10 秒、30 秒、60 秒延迟回投原队列；达到上限投死信交换机归档。
19. `MqRetryServiceImpl#handleFailure`：重发或投递死信本身失败时降级为 `basicNack(requeue=false)`，由队列死信交换机兜底。
20. `MqMessageServiceImpl#buildAndSave`：投递前把消息体序列化为 JSON，写入 `message_id`、交换机、路由键和 `class_type`。
21. `MqMessageServiceImpl#doSend`：设置 `message_id` 和 `x-delay` 消息头后发送，confirm 回调更新 `message_status`。
22. `MqMessageCompensateTask#resend`：每分钟扫描 `mq_message` 中状态为 0 或 2 且到达重发时间的记录，重发或归档。
