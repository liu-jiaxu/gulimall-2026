# 流水线环境配置与下载步骤

## 一、文档范围

这份文档只覆盖 Jenkins 流水线依赖的环境：

1. CentOS Stream 10 基础配置；
2. Docker CE 与 containerd；
3. kubeadm 单节点 Kubernetes、Flannel、local-path；
4. Jenkins、JDK、Maven、Git；
5. Jenkins 插件、凭据和流水线任务。

MySQL、Redis、应用镜像和业务清单不在这份文档中。

所有外部下载统一走代理 `http://<your-vmware-nat-ip>:7897`。

## 二、系统基础配置

### 2.1 设置主机名

> **命令说明：** 把机器主机名设置为 `gulimall-k8s`，并写入 `/etc/hosts`，让 kubelet 和 kubeadm 能解析节点名。

```bash
hostnamectl set-hostname gulimall-k8s
grep -q "gulimall-k8s" /etc/hosts || echo "<your-k8s-master-ip> gulimall-k8s" >> /etc/hosts
hostname
ping -c 1 gulimall-k8s
```

### 2.2 配置代理

> **命令说明：** 这些环境变量让当前 shell 的 curl、wget、部分脚本通过代理访问外网。`no_proxy` 保留内网和集群网段，避免集群内部通信被代理拦截。

```bash
export http_proxy=http://<your-vmware-nat-ip>:7897
export https_proxy=http://<your-vmware-nat-ip>:7897
export no_proxy=localhost,127.0.0.1,192.168.119.0/24,<your-subnet>/24,10.244.0.0/16,10.96.0.0/12,.svc,.cluster.local
```

> **命令说明：** 把同样的代理变量写入 `/etc/profile.d/proxy.sh`，新登录的 shell 自动加载。

```bash
cat > /etc/profile.d/proxy.sh <<'EOF'
export http_proxy=http://<your-vmware-nat-ip>:7897
export https_proxy=http://<your-vmware-nat-ip>:7897
export no_proxy=localhost,127.0.0.1,192.168.119.0/24,<your-subnet>/24,10.244.0.0/16,10.96.0.0/12,.svc,.cluster.local
EOF
chmod +x /etc/profile.d/proxy.sh
source /etc/profile.d/proxy.sh
```

> **命令说明：** 让 dnf 也读取代理配置。没有这一行，安装 JDK、Git、Docker 等包时可能无法访问仓库。

```bash
grep -q '^proxy=' /etc/dnf/dnf.conf || echo 'proxy=http://<your-vmware-nat-ip>:7897' >> /etc/dnf/dnf.conf
dnf makecache
```

> **命令说明：** 验证代理是否能访问 Docker、GitHub 和 Kubernetes 仓库。

```bash
curl -I https://download.docker.com
curl -I https://github.com
curl -I https://pkgs.k8s.io
```

### 2.3 关闭 swap

> **命令说明：** kubelet 要求关闭 swap。该命令关闭当前 swap，并注释 `/etc/fstab` 里的 swap 行，防止重启后自动启用。

```bash
swapoff -a
sed -ri 's/.*swap.*/#&/' /etc/fstab
free -h
swapon --show
```

### 2.4 SELinux 和 firewalld

> **命令说明：** 实验环境把 SELinux 设为 permissive，并关闭 firewalld，避免 kubelet、Flannel 和 NodePort 被拦截。

```bash
setenforce 0
sed -i 's/^SELINUX=enforcing/SELINUX=permissive/' /etc/selinux/config
getenforce

systemctl disable --now firewalld
systemctl is-active firewalld
```

### 2.5 内核模块和 sysctl

> **命令说明：** 加载 overlay 和 br_netfilter 模块，并打开网桥流量转发，Flannel 和 Pod 网络需要这些参数。

```bash
cat > /etc/modules-load.d/k8s.conf <<'EOF'
overlay
br_netfilter
EOF
modprobe overlay
modprobe br_netfilter
lsmod | grep -E 'overlay|br_netfilter'

cat > /etc/sysctl.d/99-kubernetes.conf <<'EOF'
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF
sysctl --system
sysctl net.ipv4.ip_forward
```

> **命令说明：** 确认系统使用 cgroup v2。输出必须是 `cgroup2fs`。

```bash
stat -fc %T /sys/fs/cgroup/
```

## 三、Docker CE 与 containerd

### 3.1 配置 Docker 仓库

> **命令说明：** 写入 Docker CE 的 dnf 仓库，并在仓库配置里指定代理，避免拉取 Docker 软件包失败。

```bash
cat > /etc/yum.repos.d/docker-ce.repo <<'EOF'
[docker-ce-stable]
name=Docker CE Stable - $basearch
baseurl=https://download.docker.com/linux/rhel/$releasever/$basearch/stable
enabled=1
gpgcheck=1
gpgkey=https://download.docker.com/linux/rhel/gpg
proxy=http://<your-vmware-nat-ip>:7897
EOF

dnf makecache
dnf repolist | grep -i docker
```

### 3.2 安装 Docker

> **命令说明：** 安装 Docker CE、containerd 和构建插件。Docker 用于 Jenkins 构建镜像，containerd 用于 Kubernetes 运行 Pod。

```bash
dnf install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
systemctl enable --now docker
docker version
```

### 3.3 配置 Docker 代理

> **命令说明：** Docker 守护进程拉取基础镜像时使用代理。`NO_PROXY` 保留内网和集群网段。

```bash
mkdir -p /etc/systemd/system/docker.service.d
cat > /etc/systemd/system/docker.service.d/http-proxy.conf <<'EOF'
[Service]
Environment="HTTP_PROXY=http://<your-vmware-nat-ip>:7897"
Environment="HTTPS_PROXY=http://<your-vmware-nat-ip>:7897"
Environment="NO_PROXY=localhost,127.0.0.1,192.168.119.0/24,<your-subnet>/24,10.244.0.0/16,10.96.0.0/12,.svc,.cluster.local"
EOF
systemctl daemon-reload
systemctl restart docker
systemctl show --property=Environment docker
docker run --rm hello-world
```

### 3.4 配置 containerd

> **命令说明：** 生成 containerd 默认配置，并把 cgroup 驱动改成 systemd。Kubernetes 1.34 需要该配置，否则节点可能 NotReady。

```bash
systemctl enable --now containerd
containerd config default > /etc/containerd/config.toml
sed -i 's/SystemdCgroup = false/SystemdCgroup = true/g' /etc/containerd/config.toml
grep -n "SystemdCgroup" /etc/containerd/config.toml
grep -n "sandbox_image" /etc/containerd/config.toml
```

> **命令说明：** 给 containerd 单独配置代理，因为 Docker 的代理配置不会作用于 containerd。Flannel、pause、MySQL、Redis 等镜像都由 containerd 拉取。

```bash
mkdir -p /etc/systemd/system/containerd.service.d
cat > /etc/systemd/system/containerd.service.d/http-proxy.conf <<'EOF'
[Service]
Environment="HTTP_PROXY=http://<your-vmware-nat-ip>:7897"
Environment="HTTPS_PROXY=http://<your-vmware-nat-ip>:7897"
Environment="NO_PROXY=localhost,127.0.0.1,192.168.119.0/24,<your-subnet>/24,10.244.0.0/16,10.96.0.0/12,.svc,.cluster.local"
EOF
systemctl daemon-reload
systemctl restart containerd
systemctl show --property=Environment containerd
```

> **命令说明：** 从 Kubernetes 官方镜像仓库拉取 pause 镜像，验证 containerd 代理可用。拉取成功后删除测试镜像。

```bash
ctr -n k8s.io images pull registry.k8s.io/pause:3.10
ctr -n k8s.io images rm registry.k8s.io/pause:3.10
```

## 四、Kubernetes 单节点

### 4.1 配置 Kubernetes 仓库

> **命令说明：** 写入 Kubernetes 1.34 的 dnf 仓库，并在仓库中配置代理。

```bash
cat > /etc/yum.repos.d/kubernetes.repo <<'EOF'
[kubernetes]
name=Kubernetes
baseurl=https://pkgs.k8s.io/core:/stable:/v1.34/rpm/
enabled=1
gpgcheck=1
gpgkey=https://pkgs.k8s.io/core:/stable:/v1.34/rpm/repodata/repomd.xml.key
exclude=kubelet kubeadm kubectl cri-tools kubernetes-cni
proxy=http://<your-vmware-nat-ip>:7897
EOF

dnf makecache
dnf repolist | grep -i kubernetes
```

### 4.2 安装 kubeadm、kubelet、kubectl

> **命令说明：** 安装 Kubernetes 组件并锁定版本，防止后续 dnf 升级导致版本不一致。此时只启用 kubelet，不手动启动。

```bash
dnf install -y kubelet kubeadm kubectl cri-tools --disableexcludes=kubernetes
kubeadm version -o short
kubelet --version
kubectl version --client

dnf install -y dnf-plugins-core python3-dnf-plugin-versionlock
dnf versionlock add kubelet kubeadm kubectl
systemctl enable kubelet
```

### 4.3 初始化集群

> **命令说明：** 先做一次预检，确认系统、端口、镜像和配置没有明显问题。

```bash
kubeadm init --dry-run
```

> **命令说明：** 初始化单节点控制平面，API Server 对外公布 `<your-k8s-master-ip>`，Pod 网段使用 `10.244.0.0/16`，容器运行时指定 containerd。

```bash
kubeadm init \
  --apiserver-advertise-address=<your-k8s-master-ip> \
  --pod-network-cidr=10.244.0.0/16 \
  --kubernetes-version=$(kubeadm version -o short) \
  --cri-socket=unix:///run/containerd/containerd.sock
```

> **命令说明：** 把管理员 kubeconfig 复制到 root 的 `~/.kube/config`，后续 kubectl 命令才能连接集群。

```bash
mkdir -p $HOME/.kube
cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
chown $(id -u):$(id -g) $HOME/.kube/config
kubectl cluster-info
kubectl get nodes
```

### 4.4 安装 Flannel

> **命令说明：** 通过代理下载 Flannel 清单并应用，为 Pod 提供跨节点网络。单节点也需要 CNI，否则节点一直 NotReady。

```bash
curl -x http://<your-vmware-nat-ip>:7897 -L \
  -o /tmp/kube-flannel.yml \
  https://github.com/flannel-io/flannel/releases/latest/download/kube-flannel.yml
kubectl apply -f /tmp/kube-flannel.yml
kubectl -n kube-flannel get pods -o wide
```

> **命令说明：** 单节点集群移除了控制平面污点，让业务 Pod 可以调度到该节点。

```bash
kubectl taint nodes --all node-role.kubernetes.io/control-plane-
kubectl get nodes -o wide
```

### 4.5 安装 local-path 存储

> **命令说明：** 安装 local-path-provisioner，为 MySQL、Redis 等 PVC 提供本地存储，并把 StorageClass 设为默认。

```bash
curl -x http://<your-vmware-nat-ip>:7897 -L \
  -o /tmp/local-path-storage.yaml \
  https://raw.githubusercontent.com/rancher/local-path-provisioner/v0.0.30/deploy/local-path-storage.yaml
kubectl apply -f /tmp/local-path-storage.yaml
kubectl -n local-path-storage get pods
kubectl get storageclass

kubectl patch storageclass local-path \
  -p '{"metadata":{"annotations":{"storageclass.kubernetes.io/is-default-class":"true"}}}'
kubectl get storageclass
```

### 4.6 kubelet 资源预留

> **命令说明：** 编辑 kubelet 配置，为系统和 Kubernetes 组件预留 CPU、内存和磁盘，避免业务 Pod 占满后系统组件被驱逐。下方是配置片段，需要合并到 `/var/lib/kubelet/config.yaml`。

```bash
vi /var/lib/kubelet/config.yaml
```

配置片段：

> **命令说明：** 这是 kubelet 资源预留配置片段，合并到 `/var/lib/kubelet/config.yaml` 后重启 kubelet。

```yaml
systemReserved:
  cpu: "500m"
  memory: "1Gi"
  ephemeral-storage: "2Gi"
kubeReserved:
  cpu: "500m"
  memory: "1Gi"
evictionHard:
  memory.available: "300Mi"
  nodefs.available: "10%"
```

> **命令说明：** 重启 kubelet 让资源预留配置生效，然后查看节点可分配资源。

```bash
systemctl restart kubelet
kubectl describe node gulimall-k8s | grep -A6 Allocatable
```

### 4.7 安装 metrics-server（可选）

> **命令说明：** 安装 metrics-server 后可以使用 `kubectl top` 查看节点和 Pod 的 CPU、内存占用。自签证书环境需要加上 `--kubelet-insecure-tls`。

```bash
curl -x http://<your-vmware-nat-ip>:7897 -L \
  -o /tmp/metrics-server.yaml \
  https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
kubectl apply -f /tmp/metrics-server.yaml

kubectl -n kube-system patch deployment metrics-server --type=json \
  -p '[{"op":"add","path":"/spec/template/spec/containers/0/args/-","value":"--kubelet-insecure-tls"}]'

kubectl -n kube-system get pods | grep metrics
kubectl top nodes
```

## 五、Jenkins 安装

### 5.1 安装 JDK、Git、Maven

> **命令说明：** 安装 JDK 21、Git 和编译工具。本项目使用 Java 21。

```bash
dnf install -y java-21-openjdk java-21-openjdk-devel git
java -version
javac -version
git --version
ls -d /usr/lib/jvm/java-21-openjdk*
```

> **命令说明：** 通过代理下载 Maven 3.9.9，解压到 `/opt`，并创建 `/usr/bin/mvn` 软链接，让 Jenkins 的 shell 可以直接执行 `mvn`。

```bash
cd /tmp
curl -x http://<your-vmware-nat-ip>:7897 -L \
  -o apache-maven-3.9.9-bin.tar.gz \
  https://archive.apache.org/dist/maven/maven-3/3.9.9/binaries/apache-maven-3.9.9-bin.tar.gz

tar -xzf apache-maven-3.9.9-bin.tar.gz -C /opt
ln -sfn /opt/apache-maven-3.9.9 /opt/maven
ln -sfn /opt/maven/bin/mvn /usr/bin/mvn
mvn -v
```

### 5.2 创建 Jenkins 用户

> **命令说明：** 创建独立的 Jenkins 用户和家目录，并把该用户加入 docker 组，使流水线可以执行 docker 命令。

```bash
useradd --create-home --home-dir /var/lib/jenkins --shell /bin/bash jenkins
usermod -aG docker jenkins
id jenkins
```

### 5.3 配置 Maven 代理

> **命令说明：** Maven 访问中央仓库时也走代理。为 root 和 Jenkins 用户各准备一份 `settings.xml`。

```bash
mkdir -p /root/.m2
cat > /root/.m2/settings.xml <<'EOF'
<settings>
  <proxies>
    <proxy>
      <id>local-proxy</id>
      <active>true</active>
      <protocol>http</protocol>
      <host><your-vmware-nat-ip></host>
      <port>7897</port>
      <nonProxyHosts>localhost|127.0.0.1|192.168.*|10.*</nonProxyHosts>
    </proxy>
  </proxies>
</settings>
EOF

mkdir -p /var/lib/jenkins/.m2
cp /root/.m2/settings.xml /var/lib/jenkins/.m2/settings.xml
chown -R jenkins:jenkins /var/lib/jenkins/.m2
```

### 5.4 下载 Jenkins WAR

> **命令说明：** 通过代理下载 Jenkins LTS WAR，并检查文件大小和类型。正常的 WAR 约 100MB，`file` 应返回 Java archive。

```bash
mkdir -p /opt/jenkins
curl -fL --retry 5 --retry-delay 3 --connect-timeout 20 \
  -x http://<your-vmware-nat-ip>:7897 \
  -o /opt/jenkins/jenkins.war \
  https://get.jenkins.io/war-stable/latest/jenkins.war
ls -lh /opt/jenkins/jenkins.war
file /opt/jenkins/jenkins.war
jar tf /opt/jenkins/jenkins.war | head
```

### 5.5 配置 Jenkins systemd

> **命令说明：** 把 Jenkins 注册为 systemd 服务，设置 JENKINS_HOME、JDK、代理和 PATH。服务以 jenkins 用户运行，重启后自动启动。

```bash
cat > /etc/systemd/system/jenkins.service <<'EOF'
[Unit]
Description=Jenkins
After=network.target docker.service
Requires=docker.service

[Service]
User=jenkins
Group=jenkins
Environment="JENKINS_HOME=/var/lib/jenkins"
Environment="JAVA_HOME=/usr/lib/jvm/java-21-openjdk"
Environment="JAVA_OPTS=-Xms512m -Xmx1g -Duser.timezone=Asia/Shanghai -Dfile.encoding=UTF-8"
Environment="HTTP_PROXY=http://<your-vmware-nat-ip>:7897"
Environment="HTTPS_PROXY=http://<your-vmware-nat-ip>:7897"
Environment="NO_PROXY=localhost,127.0.0.1,192.168.119.0/24,<your-subnet>/24,10.244.0.0/16,10.96.0.0/12,.svc,.cluster.local"
Environment="PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/opt/maven/bin"
ExecStart=/usr/bin/java -jar /opt/jenkins/jenkins.war --httpPort=8080
Restart=on-failure
RestartSec=10
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now jenkins
systemctl status jenkins --no-pager
```

> **命令说明：** 读取 Jenkins 首次启动生成的初始管理员密码，用于浏览器 Setup Wizard。

```bash
cat /var/lib/jenkins/secrets/initialAdminPassword
```

### 5.6 Jenkins 初始化

1. 浏览器打开 `http://<your-k8s-master-ip>:8080`；
2. 输入初始管理员密码；
3. 选择 Install suggested plugins；
4. 创建 Jenkins 管理员账号；
5. Jenkins URL 填写 `http://<your-k8s-master-ip>:8080/`；

## 六、Jenkins 凭据

### 6.1 GitHub PAT

> **命令说明：** 私有 GitHub 仓库使用 Classic PAT + `repo` 权限。这个 Token 用于 Jenkins 拉取代码。

创建步骤：

1. GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)；
2. Generate new token (classic)；
3. Scope 勾选 `repo`；
4. 生成并复制 Token。

Jenkins 凭据：

> **命令说明：** 这是 GitHub PAT 的 Jenkins 凭据字段，Kind 选 Username with password，ID 固定为 `github-pat`。

```text
Kind: Username with password
ID: github-pat
Username: liu-jiaxu
Password: Classic PAT
Description: GitHub PAT
```

### 6.2 Docker Hub Access Token

> **命令说明：** 先在 Docker Hub 创建公开仓库，再创建 Read & Write 的 Access Token。Jenkins 使用它登录 Docker Hub 并推送镜像。

创建公开仓库：

> **命令说明：** 这是 Docker Hub 公开仓库的创建步骤，Namespace 填账号名，仓库名和 Jenkinsfile 里的 IMAGE_REPO 保持一致。

```text
Docker Hub → Repositories → Create repository
Namespace: liujiaxucn
Repository name: gulimall-k8s
Visibility: Public
```

创建 Access Token：

> **命令说明：** 这是 Docker Home 中创建 Access Token 的入口和权限设置，Repository permissions 必须选择 Read & Write。

```text
https://app.docker.com/settings/personal-access-tokens
→ Generate new token
→ Repository permissions: Read & Write
→ Generate
```

Jenkins 凭据：

> **命令说明：** 这是 Docker Hub 的 Jenkins 凭据字段，Password 填 Access Token，不能填 Docker Hub 登录密码。

```text
Kind: Username with password
ID: dockerhub-credentials
Username: liujiaxucn
Password: Docker Hub Access Token
Description: Docker Hub push token
```

### 6.3 Kubernetes RBAC 和 kubeconfig

> **命令说明：** 为 Jenkins 创建命名空间级 ServiceAccount、Role 和 RoleBinding，只允许它管理 Deployment、Service、Pod 和日志，不授予集群管理员权限。

```bash
kubectl apply -f /opt/gulimall/gulimall-k8s/k8s/40-jenkins-rbac.yaml
kubectl -n gulimall-k8s get serviceaccount,role,rolebinding
```

> **命令说明：** 为 Jenkins ServiceAccount 生成一年有效期的 Token，并把 Token、CA 证书和 API Server 地址写入 kubeconfig。

```bash
CA_DATA=$(base64 -w0 /etc/kubernetes/pki/ca.crt)
TOKEN=$(kubectl -n gulimall-k8s create token jenkins-deployer --duration=8760h)

mkdir -p /var/lib/jenkins/.kube
cat > /var/lib/jenkins/.kube/config <<EOF
apiVersion: v1
kind: Config
clusters:
- name: gulimall-k8s
  cluster:
    certificate-authority-data: ${CA_DATA}
    server: https://<your-k8s-master-ip>:6443
users:
- name: jenkins-deployer
  user:
    token: ${TOKEN}
contexts:
- name: jenkins-deployer
  context:
    cluster: gulimall-k8s
    user: jenkins-deployer
    namespace: gulimall-k8s
current-context: jenkins-deployer
EOF

chown -R jenkins:jenkins /var/lib/jenkins/.kube
chmod 600 /var/lib/jenkins/.kube/config
```

> **命令说明：** 用 jenkins 用户执行一次 kubectl，验证 RBAC 是否生效。


## 九、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| Jenkins WAR 下载后无法启动 | 文件是 HTML 错误页或下载不完整 | 用 `file` 和 `jar tf` 检查，重新走代理下载 |
| Jenkins 插件下载慢 | 代理没有配置到 Jenkins | `Manage Jenkins → System → HTTP Proxy Configuration` |
| Docker 权限拒绝 | Jenkins 用户不在 docker 组 | `usermod -aG docker jenkins` 后重启 Jenkins |
| Git 拉取失败 | PAT 权限不足或代理未生效 | 用 Classic PAT + `repo`，检查 systemd 代理 |
| kubectl Forbidden | RBAC 或 kubeconfig 不对 | 用 jenkins 用户执行 `kubectl auth can-i` |
| 节点 NotReady | containerd 或 Flannel 未就绪 | 检查 `systemctl status containerd`、`kubectl -n kube-flannel get pods` |
| PVC Pending | local-path 未安装或未设为默认 | 检查 StorageClass |
