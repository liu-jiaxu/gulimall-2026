# 业务流程 13：场次到点结束与结算

## 一、设计思路

- 到点结束和管理员取消都不直接进入终态，先置 `seckill_state = 2 停止中`，等待 30 分钟宽限期让订单支付或取消收敛后再结算。
- 停止中立即删除该场次所有 `seckill:stock:{sessionId}:{skuId}`，抢购 Lua 因 key 不存在直接失败，避免结束瞬间继续卖出。
- 结算释放的是 ware 数据库中当前剩余的 `seckill_stock_locked`，不按关联表总量或 Redis 剩余值计算，避免重复释放。
- `settle_type` 区分最终状态：自然结束为 1，最终置 `3 已结束`；管理员取消为 2，最终置 `4 已取消`。
- 宽限期起点由 `stop_time` 决定，取消使用取消时刻，自然结束使用 `end_time`。
- 场次锁 `seckill:settle:lock:{sessionId}` 与关联修改、取消、删除共用；结算的 `operationId = settle:{sessionId}:{relationId}` 保证重复消费不重复释放。
- 终态更新带 `seckill_state = 2` 条件，重复结束或结算消息只生效一次。
- 删除场次按状态处理：未开始先释放剩余锁定，已结束或已取消不再释放；每天 03:00 的兜底任务补齐停止中未结算和漏结束消息的场次。

## 二、主要功能描述

**触发动作**

- 自然到点：场次保存时预约的 `seckill.end` 延时消息到期，由 `SeckillSessionEndListener` 消费。
- 管理员取消：后台场次列表点击“取消”，仅进行中场次可用。
- 管理员删除：后台场次列表点击“删除”，物理删除场次和关联记录。
- 兜底扫描：每天 03:00 由 `SeckillSettleScheduled` 执行。

**前置条件**

- 场次已存在，自然结束要求 `status = 1` 且状态为 0 或 1；取消要求有效状态为进行中。
- 删除要求场次不是进行中或停止中，且到点但未结算的场次不能删。
- coupon 能访问 ware 的释放和刷新接口，`mq_message` 表可写。

**幂等与重试**

- 结束和结算消息都可能重复投递，状态条件更新和 `operationId` 唯一索引保证不重复推进或重复释放。
- 拿不到场次锁时，`markEnding` 抛异常交给 MQ 重试，`settleSession` 静默返回并等待下一轮兜底。
- 结算消息提前到达或宽限期未到时直接返回并签收，由每天 03:00 的任务补处理。
- 删除场次不是原子操作，ware 释放、记录删除和 Redis 清理分步执行，失败时留待人工核对。

**做什么**

- 自然结束：条件更新为停止中，删除库存 key，预约宽限期后的结算消息，结算后释放剩余锁定并置已结束。
- 管理员取消：条件更新为停止中并记录 `stop_time`，删除库存 key，宽限期后结算为已取消。
- 管理员删除：未开始场次先释放剩余秒杀锁定，再删除关联、场次和 Redis key；已结算场次只删记录。
- 结算完成后删除库存 key、每人已购计数 Hash、场次商品 Hash，并按数据库重算普通可售库存缓存。

**不做什么**

- 不取消或关闭已经创建的订单，订单超时由订单侧处理。
- 不释放 `stock_locked`，只释放 `seckill_stock_locked`。
- 不退款，不修改已支付订单，不重算价格、销量或 ES 数据。

**状态结果**

| 场景 | 中间态 | 终态 | 库存处理 |
|---|---|---|---|
| 自然到点 | 停止中，`settle_type=1`，`stop_time=null` | 已结束 | 结算时释放剩余锁定 |
| 管理员取消 | 停止中，`settle_type=2`，`stop_time=now` | 已取消 | 结算时释放剩余锁定 |
| 删除未开始场次 | 无 | 记录删除 | 删除前释放剩余锁定 |
| 删除已结束或已取消 | 无 | 记录删除 | 不再释放 |
| 管理员下架 | 仅 `status=0` | 状态不变 | 不动库存和库存 key |

## 三、执行顺序

1. `SeckillSessionServiceImpl#saveSession/updateSession`：保存场次时调用 `sendEndMessage` 预约 `seckill.end` 延时消息。
2. `SeckillSessionServiceImpl#sendEndMessage`：`status=1` 且结束时间非空时计算延时，调用 `sendReliable` 写 `mq_message`。
3. `SeckillSessionEndListener#onEnd`：反序列化 `sessionId` 和 `endTimeMillis`，调用 `markEnding`，成功后签收消息。
4. `SeckillSettleServiceImpl#markEnding`：获取 `seckill:settle:lock:{sessionId}` 锁，状态更新与结算消息登记放在同一本地事务。
5. `SeckillSettleServiceImpl#doMarkEnding`：场次不存在、状态为 2/3/4、`status != 1` 或结束时间不匹配时直接返回。
6. `doMarkEnding`：当前时间早于结束时间时重投结束消息；否则条件更新状态为停止中、`settle_type=1`、`stop_time=null`。
7. `SeckillSettleServiceImpl#deleteStockKeys`：删除该场次全部 `seckill:stock:{sessionId}:{skuId}`，单个删除失败只记日志。
8. `doMarkEnding`：按 `end_time + 宽限期` 计算延时，发送 `seckill.settle` 结算消息。
9. `SeckillSettleListener#onSettle`：解析 `sessionId`，调用 `settleSession`，成功后签收消息。
10. `SeckillSettleServiceImpl#settleSession`：获取场次锁；状态不是停止中、宽限期未到或拿不到锁时直接返回。
11. `settleSession`：查 `sms_seckill_sku_relation`，逐条调 ware `releaseRemainingSeckillStock`，`operationId` 使用 `settle:{sessionId}:{relationId}`。
12. `WareSkuServiceImpl#releaseRemainingSeckillStock`：校验参数，查 `wms_seckill_stock_operation`，同一 `operationId` 已释放则返回 0。
13. `WareSkuServiceImpl#releaseRemainingSeckillStock`：`FOR UPDATE` 读取 `wms_ware_sku` 当前 `seckill_stock_locked`，为 0 直接返回。
14. `WareSkuServiceImpl#releaseRemainingSeckillStock`：`INSERT IGNORE` 写 RELEASE 记录，条件更新 `seckill_stock_locked = 0` 并返回释放量。
15. `settleSession`：按 `settle_type` 条件更新状态为已结束或已取消，条件包含当前状态仍为停止中。
16. `settleSession`：删除 stock key、`seckill:user:count:{sessionId}:{skuId}`，刷新每个 SKU 的普通库存缓存，最后删除 `seckill:session:{sessionId}:skus`。
17. `SeckillSessionController#cancel`：接收场次 id，调用 `cancelSession`。
18. `SeckillSettleServiceImpl#cancelSession`：获取场次锁，调用 `doCancel` 并在本地事务中完成状态变更与消息登记。
19. `doCancel`：已取消直接返回；停止中或已结束报错；要求 `status=1` 且有效状态为进行中。
20. `doCancel`：条件更新为停止中、`settle_type=2`、`stop_time=now`；随后删除库存 key，发送宽限期后的结算消息。
21. `SeckillSessionController#delete`：接收 id 数组，调用 `deleteSessions`，逐个场次执行 `deleteOneSession`。
22. `SeckillSettleServiceImpl#deleteOneSession`：获取场次锁；进行中或停止中拒绝；已到结束时间但未结算的拒绝。
23. `deleteOneSession`：未开始或下架未结算的场次逐条调 `releaseRemainingSeckillStock`，`operationId` 使用 `delete:{sessionId}:{relationId}`。
24. `deleteOneSession`：删除该场次关联和场次记录，删除库存 key、已购计数和商品 Hash，刷新普通库存缓存。
25. `SeckillSettleScheduled#settleStoppingSessions`：每天 03:00 对宽限期已到的停止中场次调 `settleSession`。
26. `SeckillSettleScheduled#settleStoppingSessions`：对状态仍为 0/1、已启用且结束时间早于宽限期截止的场次，先 `markEnding` 再 `settleSession`。
