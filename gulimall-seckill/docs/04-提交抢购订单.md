# 业务流程 04：提交抢购订单

## 一、设计思路

- 抢购入口按“登录拦截 → Sentinel → 参数与幂等 → Lua 预扣 → 本地事务 → 可靠消息”分层，前置层被拦时不会消耗库存。
- Redis Lua 在单次脚本内完成库存校验、时间窗口、防重、限购、扣库存、加已购、写预扣标识，保证并发下不超卖。
- 两层幂等：按 `requestId` 查 `sms_seckill_order` 返回原结果；10 秒防重 key 拦截换 `requestId` 的重复请求。
- 商品价格、限购、随机码只信任 Redis Hash，不信任前端传参；`randomCode` 不一致直接拒绝。
- 预扣单与 `mq_message` 在同一本地事务写入，事务提交后由 `afterCommit` 投递，业务数据与消息记录一致。
- MQ 投递失败不阻断抢购结果，消息保留待确认状态由补偿任务重发；落库失败则调用释放脚本回补 Redis。
- 释放脚本带 7 天幂等标识，避免延迟消息重复回补；库存 key 不存在时不回补。
- 业务异常统一转 `{code,msg}` JSON，错误码覆盖未登录、未开始、已结束、库存不足、限购、随机码、限流等。

## 二、主要功能描述

**触发动作**：确认页点击“提交抢购”，浏览器发送 `POST /seckill/order/submit`。

**前置条件**：已登录；有默认收货地址；商品 Hash 与库存 key 存在；当前时间在秒杀时段内；`randomCode` 与 Hash 一致。

**流程职责**：
- 校验登录、参数与 `requestId` 幂等。
- 校验商品快照、随机码与时间窗口。
- 原子预扣库存与限购计数，写防重与预扣标识。
- 落 `sms_seckill_order`（status=0）与 `mq_message`（status=0）。
- 事务提交后投递建单消息，返回排队状态。

**不包含**：
- 不创建 `oms_order`，由流程 06 异步建单。
- 不扣减 `wms_ware_sku`，不锁订单库存。
- 不支付，不把订单推进为已建单。
- 不校验 `addrId` 是否属于当前会员。
- 不做结果轮询。

**结果**：
- 成功：返回 `orderSn`、`status=0`、`statusText=排队建单中`、`payAmount`。
- 失败：返回对应业务码，库存与已购保持提交前状态，或已通过释放脚本回补。
- 状态值：0 待建单、1 已建单、2 已释放、3 建单失败、4 已支付；本流程只产生 0。

**异常与降级**：
- 未登录：拦截器返回 14001，不进入 Sentinel，不扣库存。
- Sentinel 限流或熔断：返回 14013，不进入业务。
- Hash 缺失或随机码不一致：返回 14011 或 14007，不回源数据库。
- 库存不足、超限购、未开始、已结束：Lua 返回负数码并映射为 14004、14005、14002、14003。
- 落库或写消息异常：事务回滚，释放脚本回补 Redis，返回 14012。
- MQ 投递失败：业务仍返回排队状态，`mq_message` 等待补偿重发。

**数据与缓存**：
- `sms_seckill_order`：按 `request_id` 读，成功插入 status=0。
- `mq_message`：同事务插入 status=0，confirm 后更新为 1 或 2。
- `seckill:stock:{sessionId}:{skuId}`：Lua 读取并 `DECRBY`。
- `seckill:user:count:{sessionId}:{skuId}`：Lua 读取并 `HINCRBY`。
- `seckill:req:*`：10 秒防重；`seckill:reserve:*`：30 分钟预扣标识；`seckill:release:*`：7 天释放幂等。

## 三、执行顺序

1. Nginx：`POST /seckill/order/submit` 命中秒杀站点，转发到 14000；直连入口不经过网关。
2. `LoginUserInterceptor#preHandle`：从共享 Session 取 `LOGIN_USER`，放入 ThreadLocal。
3. 未登录：直接写 HTTP 200 与 `{code:14001}` JSON，不进入 Controller 与 Sentinel。
4. `SeckillOrderController#submit`：进入 `@SentinelResource("seckillOrderSubmit")`。
5. Sentinel 拦截：50 QPS 流控或慢调用熔断触发时走 `submitBlocked`，返回 14013。
6. `SeckillOrderController#currentMember`：从 ThreadLocal 取会员，为空时再抛 14001。
7. `SeckillOrderServiceImpl#submit`：校验会员、`sessionId`、`skuId`、`addrId`、`requestId`、`quantity`，不合法返回 14009。
8. 按 `request_id` 查 `sms_seckill_order`：已存在则直接 `toResult` 返回，不再扣减。
9. 读 `HGET seckill:session:{sessionId}:skus {skuId}`：缺失或解析失败返回 14011。
10. 校验 `randomCode` 与 Hash 一致，`wareId` 与 `seckillPrice` 非空；不满足返回 14007 或 14011。
11. 校验时间窗口：`now < startTime` 返回 14002，`now >= endTime` 返回 14003。
12. `SeckillOrderServiceImpl#generateOrderSn`：生成 14 位时间、4 位会员尾号与 6 位随机数。
13. `SeckillStockServiceImpl#tryReserve`：执行 `RESERVE_SCRIPT`，传入库存、限购、防重、预扣标识 4 个 key。
14. Lua 校验：库存 key 不存在返回 -1；未开始返回 -4；已结束返回 -5；防重 key 存在返回 2 与原 `orderSn`。
15. Lua 校验：`bought + quantity > limit` 返回 -3；`stock < quantity` 返回 -2。
16. Lua 写入：`DECRBY` 库存，`HINCRBY` 已购，同步限购 Hash 的 TTL，写 10 秒防重 key 与 30 分钟预扣标识。
17. Lua 返回 2：按原 `orderSn` 查预扣单，查到返回原结果，查不到返回“排队建单中”的临时结果。
18. 其它负数码：`mapReserveCode` 转为 14004、14005、14002、14003；-1 归为 14011。
19. `SeckillOrderServiceImpl#createReservedOrder`：用 Hash 快照组装预扣单，`status=0`、`build_retry_count=0`。
20. 本地事务：插入 `sms_seckill_order`，调用 `MqMessageService#sendReliable` 插入 `mq_message`。
21. 事务提交后 `afterCommit`：`MqMessageServiceImpl#doSend` 投递到 `gulimall-seckill-order-exchange`，路由键 `seckill.order.create`。
22. Broker 确认：ack 把 `mq_message.message_status` 改为 1；nack 或 return 改为 2，等待补偿任务重发。
23. 落库、序列化或事务异常：调用 `releaseReservation` 执行释放脚本，回补库存与已购，返回 14012。
24. 释放脚本：释放标识已存在返回 0；库存 key 不存在返回 -1；正常则 `INCRBY` 库存、`HINCRBY -quantity`、写 7 天释放标识。
25. 异常与返回：`SeckillExceptionControllerAdvice` 把 `RRException` 转对应码、其它异常转 99000；正常返回 `R.ok().put("seckillOrder", ...)`，前端取 `orderSn` 进入流程 05。
