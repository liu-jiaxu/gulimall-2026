# 新模块静态资源接入 Nginx

> 给项目新增一个**带页面的模块**时，按这三步走。已有的 product / search / item 就是这么配的，
> 原理详见 **`Nginx.md`** 的「静态资源的目录约定」。

---

## 先判断：要不要改 nginx

静态资源由 nginx 直出，靠的是 `root html/` + `try_files` 回退。所以：

| 情况 | nginx 要改什么 |
|---|---|
| 往**已有模块**（product / search）加资源 | **不用改** —— 文件拷到 `html/<模块>/` 即可 |
| **新模块**，复用现有域名 | **不用改** —— 同上 |
| **新模块 + 新域名** | 加一个 `server` 块 + hosts 一行（见文末模板） |

---

## 三步法

### 1. 静态资源目录平移

```
<模块>/src/main/resources/static/<X>/   →   nginx 的 html/<X>/
```

规则只有一条：**`static/<X>` → `html/<X>`**。

```bash
# 例：auth-server
mkdir -p /mydata/docker/nginx/html/{login,reg}
scp -r gulimall-auth-server/src/main/resources/static/login/* root@<IP>:/mydata/docker/nginx/html/login/
scp -r gulimall-auth-server/src/main/resources/static/reg/*   root@<IP>:/mydata/docker/nginx/html/reg/
```

### 2. 页面引用加模块名前缀

**相对路径是相对「页面 URL」解析的**，不是相对文件在磁盘上的位置：

```diff
- <img src="JD_img/logo.jpg">
+ <img src="login/JD_img/logo.jpg">
```

```
页面 URL      http://auth.gulimall.vip/login.html
改前          解析成 /JD_img/logo.jpg              → 磁盘 html/JD_img/…      ✗ 404
改后          解析成 /login/JD_img/logo.jpg        → 磁盘 html/login/JD_img/… ✓ 命中
```

漏了这一步的症状：**页面能打开，但图片 / 样式全裂**。

### 3. Controller 用根级路径

```java
@GetMapping({"/", "/login.html"})
public String loginPage() { return "login"; }

@GetMapping("/reg.html")
public String regPage() { return "reg"; }
```

⚠️ **不能写成 `/auth/login.html`** —— 多一层子路径，第 2 步的相对引用会拼成
`/auth/login/JD_img/...`，又会全裂。

## 需要新域名时

在 `gulimall.conf` 末尾加一个 `server` 块：

```nginx
server {
    listen 80;
    server_name auth.gulimall.vip;

    # ★ root 指到 html/（不是 html/auth）—— 因为页面引用带模块前缀
    root /usr/share/nginx/html;

    # 图片走 /oss/ → MinIO
    include /etc/nginx/conf.d/img-proxy.inc;

    # 静态资源：本地有就直出，没有回退给后端
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|webp|woff2?|ttf|eot)$ {
        try_files $uri @backend;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    location @backend {
        proxy_pass http://host.docker.internal:20000;      # ← 改成本模块端口
        proxy_set_header Host            $host;
        proxy_set_header X-Real-IP       $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location / {
        proxy_pass http://host.docker.internal:20000;      # ← 同上一处
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

配套两处：

```bash
mkdir -p /mydata/docker/nginx/html/<新目录>          # ① 建静态资源目录
```

```
<your-vm-host-ip>  auth.gulimall.vip                   # ② 访问端的 hosts 加一行
```

改完 `.conf` 要 **`docker compose restart nginx`** 才生效。

---

## 两个坑

| 坑 | 说明 |
|---|---|
| **文件名大小写** | Windows 不区分、**Linux 区分**。`bootStrap` / `bootstrap` 混用会「本地正常、服务器 404」 |
| **改静态资源不用重启** | 静态文件是 nginx 直出，拷过去即可生效；**只有改 `.conf` 才需要重启 nginx** |
