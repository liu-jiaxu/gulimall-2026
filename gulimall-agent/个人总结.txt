策略 + 工厂模式 创建AI模型
1.yaml列举所有AI模型
2.服务启动后读取yaml中的AI模型配置信息
3.使用工厂创建全部的AI模型对象
4.使用时注入List集合存储全部AI模型，根据用户指定AI名称从List中查询具体AI模型信息
5.找到模型后开始对话，同时后续对话会复用当前设置，不会每次对话都创建AI模型

JWT + RS256鉴权
1.用户登录成功，将用户基本信息使用JWT的RSA私钥方式签名，存储至前端
2.需要身份验证的请求，请求头的cookie都会带上这个签名
3.验证时使用公钥验签，对比身份信息，同时查看签名是否过期等
4.TTL30min + 过期自动重新鉴权

RAG切分
1. 按标题切分：识别 #/##/###（h1~h3）逐行扫描，用 fenced 标志排除代码块内的 #。
2. 按 Token 切分：对超长章节按 800 token 二次切分，用二分查找定位 token 边界（jtokkit 只能整段 encode）。
3. 代码块保护：技术文档模式下正则   [\s\S]*?  分离代码块，代码块作为原子单元不被切断。
4. Overlap 重叠：getLastTokens 取前段末尾 overlap（50）个 token 作为下一段开头，保证语义连续。
5. tokenizer 用 jtokkit 的 EncodingRegistry（deepseek 无官方 tokenizer，用 gpt-4o-mini 近似）。
6. 无 tokenizer 时退化为按字符切分，保证可用性。

天气查询步骤(WeatherTools)
1.从当前请求的 agent JWT Cookie 中解析登录身份  
2.按请求域名选择 Cookie，并校验 agent JWT。  
3.生成当前登录身份  
4.开始普通对话 
  1)校验请求并准备会话、模型、用户消息等本次对话所需的中间数据。
      用户是否发送消息图片
      读取用户默认设置（模型，提示词），DB查询
  2)同一个会话串行处理，避免两条消息同时写乱记忆 Redis锁
  3)调用AI模型
      (1)按会话 id 隔离记忆；窗口只保留最近 40 条
      (2)追加系统提示词
      (3)判断当前模型是否可以调用tool，RAG是否启动
      (4)实际调用阿里云天气查询API，若失败则降级为天气查询通用接口（返回数据乱需要手动处理）
      (5)手动处理天气结果，阿里云接口直接返回JSON数据AI可以直接获取
      (6)调用AI模型回答问题
      (7)释放Redis锁
  4)将用户提问与AI回答存储进Redis，TTL=3day，便于用户查看历史记录
