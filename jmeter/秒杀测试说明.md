# 秒杀 Sentinel 压测说明

对应规则：

| 测试文件 | 目标资源 | 规则 |
|---|---|---|
| `秒杀-网关场次查询限流.jmx` | gateway 路由 `seckill-route` | 100 QPS |
| `秒杀-商品列表直连限流.jmx` | seckill `/seckill/skus` | 200 QPS |
| `秒杀-商品详情热点参数.jmx` | `seckillSkuInfo` + `skuId` | 同一 skuId 20 次/秒 |
| `秒杀-抢购接口限流.jmx` | `seckillOrderSubmit` | 50 QPS |

## 一、通用准备

1. 启动 Sentinel Dashboard、Jaeger：
   ```bash
   cd /mydata/docker
   docker compose up -d sentinel-dashboard jaeger
   ```
2. Nacos 里确认 `SENTINEL_GROUP` 下 4 个规则 Data ID 已存在（`deploy/sentinel/`）。
3. 重启后面列出的业务服务。
4. 浏览器登录后，F12 → Application → Cookies，复制 `GULIMALLSESSION` 的值；或从登录响应头 `Set-Cookie` 里取。
5. 取当前秒杀活动的 `randomCode`：
   ```bash
   redis-cli -h <your-vm-host-ip> -p 6379 -a <your-password> hget seckill:session:14:skus 5
   ```
   取出来的 JSON 里 `randomCode` 字段就是抢购测试要用的值。

## 二、变量怎么改

每个 JMX 打开后，在 Test Plan → User Defined Variables 改：

- `targetHost`：默认 `<your-vm-host-ip>`（Nginx 所在虚拟机）
- `targetPort`：默认 `80`
- `siteHost`：网关测试用 `gulimall.vip`，秒杀直连用 `seckill.gulimall.vip`
- `sessionId`：默认 `14`（长期测试秒杀）
- `skuId`：默认 `5`
- `addrId`：抢购测试用，默认 `2`（测试会员 liu-jiaxu296 的默认地址；换成你自己的地址 id。如果换用 centeruser2026 的 cookie，则改成 `6`）
- `gulimallSession`：登录 cookie 的 GULIMALLSESSION 值。文件里预置了当前测试会员的值，过期后替换
- `randomCode`：Redis hash 里的随机码 seckill:session:14:skus。文件里预置了当前场次的值，换场次后替换

只测 Sentinel 限流时，`randomCode` / cookie 不正确也能压到接口，只是业务会返回 14007/14008；要测完整抢购则必须填对。

## 三、各测试预期

### 1. 秒杀-网关场次查询限流

- 200 线程，ramp 1 秒，循环 5 次
- 超过 100 QPS 的请求应返回 HTTP **429**，body：
  ```json
  {"code":14013,"msg":"当前抢购人数过多，请稍后再试"}
  ```
- 如果全是 200，检查 gateway 的 `gulimall-gateway-sentinel-gw-flow.json` 是否加载、`resource` 是否等于 `seckill-route`。

### 2. 秒杀-商品列表直连限流

- 300 线程，ramp 1 秒，循环 5 次
- 超过 200 QPS 的请求返回 `14013`。
- 这是直连 Nginx 的 `seckill.gulimall.vip`，不经过网关，用来单独验证 seckill Web 资源。

### 3. 秒杀-商品详情热点参数

- 100 线程，ramp 1 秒，循环 10 次，全部请求同一个 `skuId`
- 同一 skuId 每秒超过 20 次后返回 `14013`。
- 如果所有请求都成功，确认热点规则 `paramIdx=1`（`skuInfo` 的第二个参数）以及资源名 `seckillSkuInfo`。

### 4. 秒杀-抢购接口限流

- 100 线程，ramp 1 秒，循环 5 次
- 同一会员、限购 2 件，业务上大部分请求会返回：
  - `14013`：Sentinel 流控/熔断
  - `14005`：超过每人限购
  - `14004`：库存不足
  - `0`：抢购成功（最多 2 单）
- 这个测试会真实消耗活动库存/生成订单，压完记得清理测试订单或取消订单。

## 四、清场

抢购测试会生成 `sms_seckill_order`/`oms_order`，测试后按之前的测试数据清理方式处理，或调用订单取消接口释放库存。
