# 业务流程 08：订单超时关闭回补

## 一、设计思路

- 超时关单完全由定时任务驱动：`OrderTimeoutTask` 每分钟扫描 `status=0` 且创建时间超过 `delay-ms` 的订单，单批最多 100 条。
- 关单用 `status 0→4` 条件更新与支付回调互斥，只有一方成功，已支付订单不会被超时任务覆盖。
- 秒杀订单与普通订单分流：秒杀单关单后同步调用 seckill 释放；普通单关单任务只改状态，库存释放与关单解耦。
- 普通订单的释放依据下单时登记到 `mq_message` 的延时消息，到期后经延迟交换机进入 `gulimall-stock-release-queue`。
- 秒杀释放复用用户取消链路：场次锁、回池判断、`task_status 1→2` 抢占、Redis Lua 标记共同保证幂等。
- 两级兜底：普通单由 `StockReleaseTask` 在 `delay+grace` 后扫描工作单；秒杀单由 `SeckillOrderReconcileTask` 在支付超时后按 order 状态补释放。
- 系统没有订单关闭延时 MQ、没有 `closeOrder` 方法和关闭事件表，最终一致性依赖状态机、条件更新和定时对账。
- 关单成功后关闭支付宝交易，失败只记日志；已关闭订单的迟到支付由支付回调走自动退款。

关键状态：`oms_order.status` 的 `0` 待付款、`1` 待发货、`4` 已关闭；`wms_ware_order_task.task_status` 的 `1` 已锁定、`2` 已解锁、`3` 已扣减。
关键键：`seckill:settle:lock:{sessionId}`、`seckill:stock:{sessionId}:{skuId}`、`gulimall:ware:stock:{skuId}`。

## 二、主要功能描述

### 触发与前置

- 触发：`OrderTimeoutTask#closeExpiredOrders`，cron 为 `0 * * * * ?`，没有用户点击动作。
- 前置：order、seckill、ware 均开启 `@EnableScheduling`；`gulimall.ware.stock-release.delay-ms` 已配置；订单为待付款且创建时间超过超时阈值。

### 处理内容

- 分批扫描超时未支付订单，逐单条件更新为已关闭，成功后关闭支付宝交易。
- 秒杀订单立即调用 `afterOrderClosed`，经 seckill 的 `releaseByOrderSn` 释放库存并回补 Redis，秒杀单 `1→2`。
- 普通订单不直接调用 ware，等待下单时登记的延时解锁消息；消息失败由 MQ 重试和定时任务兜底。
- 秒杀释放失败由对账任务在订单创建超过 `payTimeout+5 分钟` 后查询 order 状态补处理。

### 不处理内容

- 不删除订单、不修改订单明细、不恢复购物车。
- 不关已支付、已发货、已完成订单，条件更新会挡住。
- 普通订单关单任务不直接调 ware，秒杀订单也不走 ware 普通释放链。
- 不做迟到支付的退款，退款由支付回调处理。

### 最终结果

- 订单：`oms_order.status=4`，支付宝交易尽量关闭。
- 普通订单：工作单 `task_status=2`、明细 `lock_status=2`，`stock_locked` 减少，Redis 普通库存增加。
- 秒杀订单：`sms_seckill_order.status=2`、`release_reason=ORDER_TIMEOUT`；回秒杀池时 `seckill_stock_locked` 增加并回补 Redis，回普通池时只减 `stock_locked`。
- 迟到支付：订单保持关闭，由 `refundLatePayment` 全额退款。

| 时间线 | 触发来源 | 处理结果 |
|---|---|---|
| 关单 | `OrderTimeoutTask` 每分钟扫描 | `oms_order.status 0→4`，关闭支付宝交易 |
| 库存释放 | 延时消息与 `StockReleaseTask` | 工作单 `1→2`，`stock_locked` 减少 |

### 异常与降级

- 支付回调先到：条件更新 0 行，超时任务跳过，不关单、不释放库存。
- 支付宝关闭失败：只记日志；迟到支付由支付回调识别已关闭并自动退款。
- seckill 不可用：Feign fallback 或异常只记日志，由秒杀对账任务补释放。
- 普通释放失败：MQ 按 10s/30s/60s 重试，3 次后死信；`StockReleaseTask` 在 `delay+grace` 后兜底。
- 待关闭订单超过 100 单：本轮只处理 100 单，其余顺延到下一分钟。

## 三、执行顺序

1. `OrderTimeoutTask#closeExpiredOrders`：每分钟执行，按 `now - payTimeoutMs` 计算截止时间。
2. 同上：查询 `status=0` 且 `create_time <= deadline` 的订单，只取 `id`、`order_sn`、`source_type`，`LIMIT 100`。
3. 同上：逐单条件更新 `status 0→4`，条件为 `id` 与 `status=0`；0 行表示已被支付回调或其它实例处理。
4. 同上：更新成功后调用 `AlipayService#closeTradeQuietly`，失败只记日志。
5. 同上：`source_type=2` 时调用 `OrderServiceImpl#afterOrderClosed(order, "ORDER_TIMEOUT")`；普通单不在关单任务中释放。
6. `OrderServiceImpl#afterOrderClosed` → `SeckillFeignClient#releaseSeckillOrder`：请求 `/internal/seckill/order/release`。
7. `SeckillOrderInternalController#release` → `SeckillOrderServiceImpl#releaseByOrderSn`：按 `order_sn` 查预扣单，无记录返回 `null`。
8. 同上：状态不是 `BUILT` 直接返回；获取 `seckill:settle:lock:{sessionId}`，锁内重查。
9. `SeckillOrderServiceImpl#decideReleaseMode`：场次有效状态为 `RUNNING` 且库存 key 存在时回秒杀池，否则回普通池。
10. `WareFeignClient#releaseSeckillOrderStock` → `WareSkuServiceImpl#releaseSeckillOrderStock`：查工作单并校验 `biz_type=1`。
11. 同上：条件更新 `task_status 1→2` 抢占；明细减 `stock_locked`，`SECKILL_POOL` 时加 `seckill_stock_locked`，`lock_status 1→2`。
12. 同上：事务提交后 `refreshStockCache` 按数据库重算普通库存缓存。
13. `SeckillStockServiceImpl#releaseReservation`：`SECKILL_POOL` 时 Lua 回补 `seckill:stock`、`seckill:user:count` 并写 `seckill:release`。
14. `SeckillOrderServiceImpl#releaseByOrderSn`：条件更新 `status 1→2`，写 `release_mode`、`release_reason=ORDER_TIMEOUT`。
15. 普通单：下单时 `WareSkuServiceImpl#lockStock` 已写工作单并调用 `sendReleaseMessage`，后者只把 `StockReleaseMessage` 写入 `mq_message`。
16. `MqMessageService` 补偿任务：全局事务结束后投递到延迟交换机，`x-delay` 为 `delay-ms`，到期路由到 `gulimall-stock-release-queue`。
17. `StockReleaseListener#onStockRelease`：解析 `StockReleaseMessage`，调用 `StockReleaseExecutor#release`；异常交给 `MqRetryService`。
18. `StockReleaseExecutor#release`：获取 `gulimall:ware:stock:lock` 读锁 3 秒，调用 `WareSkuServiceImpl#releaseStock`。
19. `WareSkuServiceImpl#releaseStock`：`biz_type=1` 跳过；条件更新 `task_status 1→2` 抢占；明细减 `stock_locked`、`lock_status 1→2`。
20. 同上：事务提交后 `INCRBY gulimall:ware:stock:{skuId} num`，`stock` 不变。
21. `StockReleaseTask#releaseExpiredTasks`：每分钟扫 `task_status=1`、`biz_type=0`、`create_time <= now-(delay+grace)` 的工作单，逐单调用 release。
22. `SeckillOrderReconcileTask#reconcileClosedOrders`：每分钟第 15 秒扫 `status=BUILT` 且创建超过 `payTimeout+5 分钟` 的秒杀单。
23. 同上：查 order 状态；`4` 调用 `releaseByOrderSn("RECONCILE_CLOSED")`，`1/2/3` 回填 `PAID`，`0` 继续等待。
24. 异常分支：普通释放失败进入 `MqRetryService` 重试，重试用尽进死信；`StockReleaseTask` 仍在宽限期后兜底。
