# 业务流程 01：打开秒杀页

## 一、设计思路

- 秒杀页由 `gulimall-seckill` 服务端渲染，`seckill.gulimall.vip` 经 Nginx 直接反代到 14000，不经过网关，页面请求不依赖网关路由。
- 场次只展示启用（`status=1`）、`seckill_state IN (0,1)`、未结束且 3 天内开始的记录，与自动上架的时间窗口保持一致。
- 商品信息优先读 Redis Hash `seckill:session:{sessionId}:skus`，减少 `sms_seckill_sku_relation` 与 product 的访问。
- Hash 缺失、Redis 异常或全部 JSON 解析失败时回源关联表与 product，并回填 Hash，TTL 为场次结束时间加 1 天。
- 降级只补商品 Hash，不创建 `seckill:stock:*`，避免在没有库存依据的情况下放出可抢信号。
- 场次状态由 `SeckillSessionState.effectiveState` 计算：人工的停止中、已结束、已取消优先，其余按开始与结束时间推导。
- `randomCode` 优先沿用 Hash 中已有的值，只有缺失时才生成新值，防止刷新任务让已下发到页面的随机码失效。
- 页面对游客开放，登录态只影响右上角展示，不影响场次与商品查询。

## 二、主要功能描述

**触发动作**：在商城首页点击顶部“秒杀”导航，打开 `http://seckill.gulimall.vip/seckill.html`。

**前置条件**：seckill 服务可用；Nacos、MySQL `gulimall_sms`、Redis 正常；存在可展示场次，且场次下至少有一个 SKU 能取到商品信息。

**流程职责**：
- 查询可展示场次，按开始时间升序返回。
- 为每个场次组装商品卡片：秒杀价、划线原价、每人限购、图片、名称。
- 丢弃没有商品的场次，避免页面出现空场次卡片。
- 每秒刷新场次倒计时。
- 商品卡片携带 `skuId` 与 `seckillSessionId`，点击后进入商品详情页。

**不包含**：
- 不要求登录，游客也能浏览场次与商品。
- 不读取 `seckill:stock:*` 与 `seckill:user:count:*`，页面不展示库存与已购。
- 不扣库存、不创建订单、不发送 MQ、不写数据库。
- 商品 Hash 缺失时不会凭空创建库存 key。

**结果**：
- 有可展示场次时，按开始时间升序展示场次卡片，场次内商品按 `seckillSort` 升序。
- 场次为空或全部场次没有商品时，展示空态文案。
- 倒计时进行中显示“距结束”，未开始显示“距开始”，剩余时间超过 365 天显示“长期有效”。

**异常与降级**：
- Redis 读取商品 Hash 异常：记录告警日志并回源数据库。
- Hash 部分商品 JSON 损坏：只跳过损坏条目，其它商品正常展示；全部损坏才整体回源。
- product 不可用：跳过该 SKU；场次没有可用商品时不展示。
- 回填 Hash 失败：只记录告警，当次仍返回数据，下次访问继续回源。

**展示规则**：
- `status=1` 且 `seckill_state` 为 0 或 1。
- `end_time` 不小于当前时间，`start_time` 不超过当前时间加 3 天。
- 场次下至少有一个能取到商品信息的 SKU。

**数据与缓存**：
- `sms_seckill_session`：始终读取场次信息。
- `sms_seckill_sku_relation`：仅在商品缓存回源时读取。
- product：仅在商品缓存回源时读取 SKU 名称、价格、默认图。
- `seckill:session:{sessionId}:skus`：读优先，回源后写入，field 为 `skuId`。
- `seckill:stock:*`、`seckill:user:count:*`：不读不写。

## 三、执行顺序

1. Nginx：`GET /seckill.html` 命中秒杀站点，转发到 `gulimall-seckill:14000`。
2. `SeckillPageController#seckillPage`：进入页面入口，调用场次查询服务。
3. `SeckillSkuServiceImpl#listSessionsWithSkus`：遍历可展示场次并组装页面 VO。
4. `SeckillSkuServiceImpl#listActiveSessions`：按启用状态、场次状态、结束时间、3 天窗口查询 `sms_seckill_session`。
5. 查询结果按 `start_time` 升序返回；下架、停止中、已结束、已取消、开始时间超过 3 天的场次被过滤。
6. `SeckillSkuServiceImpl#buildHomeVo`：复制场次 id、名称，并把起止时间转成毫秒时间戳。
7. `SeckillSessionState#effectiveState`：人工状态为 2/3/4 时直接返回，其余按当前时间计算未开始、进行中、已结束。
8. `SeckillSkuServiceImpl#getSessionSkus`：先读取 `seckill:session:{sessionId}:skus`。
9. `HGETALL` 命中：逐个反序列化为 `SeckillSkuVo`，单条解析失败只跳过该条。
10. 缓存为空、Redis 异常或全部 JSON 解析失败：转入 `loadSessionSkusFromDb` 回源。
11. `SeckillSkuServiceImpl#loadSessionSkusFromDb`：按场次 id 查 `sms_seckill_session`，时间不完整时返回空列表。
12. 按 `promotion_session_id` 查 `sms_seckill_sku_relation`，按 `seckill_sort` 升序。
13. `SeckillSkuServiceImpl#getProductSku`：通过 `ProductFeignClient#getSkuInfo` 查询 SKU 名称、价格、默认图。
14. product 不可用：`ProductFeignClientFallback#getSkuInfo` 返回空结果，该 SKU 被跳过。
15. `SeckillSkuServiceImpl#buildSkuVo`：合并场次、关联表、商品数据，组装 `SeckillSkuVo`。
16. `SeckillSkuServiceImpl#resolveRandomCode`：旧 Hash 中有 `randomCode` 就沿用，否则生成 UUID 去横线的值。
17. `SeckillSkuServiceImpl#cacheSku`：把商品 JSON 写回 Hash，TTL 为场次结束加 1 天；不创建库存 key。
18. 商品列表按 `seckillSort` 升序排序，`null` 排在最后。
19. 商品为空的场次不加入结果，避免页面出现无法购买的场次。
20. `SeckillPageController#seckillPage`：从共享 Session 读取 `LOGIN_USER`，游客为 null。
21. 把 `sessions`、`itemUrl`、`authUrl`、`shopHomeUrl`、`loginUser` 放入 Model，返回视图 `seckill`。
22. Thymeleaf：渲染场次卡片、商品卡片、秒杀价、划线原价与每人限购。
23. 浏览器：为每个场次启动 1 秒倒计时；目标时间按状态取 `endTime` 或 `startTime`。
24. 点击商品卡片：跳转 `item.html?skuId=...&seckillSessionId=...`，进入流程 02。
