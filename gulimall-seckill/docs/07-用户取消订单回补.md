# 业务流程 07：用户取消订单回补

## 一、设计思路

- 取消只处理待付款订单：用 `status 0→4` 条件更新与支付回调、超时关单竞争，只有一方能成功，避免已支付订单被关闭。
- 已关闭订单再次取消按幂等处理：重新触发下游释放，靠下游条件更新补齐上次可能失败的释放。
- 按 `source_type` 分流：秒杀订单交给 seckill 判断回哪个池，普通订单直接走 ware；两条库存口径互不混用。
- 回池条件严格：场次存在且有效状态为 `RUNNING`、Redis 库存 key 仍存在，才回秒杀池；否则回普通可售池，避免凭空补库存。
- 场次锁 `seckill:settle:lock:{sessionId}` 与结算、取消共用，`tryLock` 3 秒并在锁内重查，防止判断进行中与结算删 key 交叉。
- 先数据库后缓存：ware 用 `task_status 1→2` 抢占释放，再改 `stock_locked`；Redis 仅在事务提交后回补，Lua 用 `seckill:release:{orderSn}` 标记保留 7 天防重复。
- 释放失败不回滚取消：seckill、ware 的失败只记日志，订单仍返回取消成功，由秒杀对账任务和库存兜底任务补齐。
- 普通订单 Redis 用 `INCRBY` 而不是查库后 `SET`，避免并发预扣时用旧值覆盖新值。

关键状态：秒杀单 `BUILT(1)` 只能推进到 `RELEASED(2)`；`release_mode=1` 回秒杀池，`2` 回普通池。
关键键：`seckill:settle:lock:{sessionId}`、`seckill:stock:{sessionId}:{skuId}`、`seckill:release:{orderSn}`。

## 二、主要功能描述

### 触发与前置

- 触发：支付页、订单列表、订单详情点击“取消订单”，统一调用 `POST /pay/cancel`，参数 `orderSn`。
- 前置：请求经过登录拦截器；订单存在且 `member_id` 等于当前会员；状态为 `0`；秒杀单还需 `sms_seckill_order.status=1`；Redisson 与 ware 可用。

### 处理内容

- 条件更新 `oms_order.status 0→4`，成功后调用支付宝 `alipay.trade.close` 关闭交易，失败仅记录。
- 秒杀订单调用 seckill `/internal/seckill/order/release`：判断回池模式、释放 ware 库存、回补 Redis、把秒杀单 `1→2`。
- 普通订单调用 ware `/ware/waresku/releaseByOrderSn`：工作单 `1→2`、`stock_locked` 减回、Redis 普通库存 `INCRBY`。
- 已关闭订单重复取消时重新执行释放，依靠工作单状态和 Redis 标记保证只释放一次。

### 不处理内容

- 不退款、不删除订单、不改订单明细、不恢复购物车。
- 不发送新 MQ；普通订单下单时登记的延时解锁消息到期后会因工作单已释放而跳过。
- 不修改 10 秒防重 key；场次停止中、已结束或已取消时不回秒杀池。

### 最终结果

- 普通订单：`oms_order.status=4`，工作单 `task_status=2`，明细 `lock_status=2`，`stock_locked` 减少，`gulimall:ware:stock:{skuId}` 增加。
- 秒杀订单回秒杀池：秒杀单 `status=2`、`release_mode=1`，`stock_locked` 减少、`seckill_stock_locked` 增加，Redis 秒杀库存和限购回补。
- 秒杀订单回普通池：`release_mode=2`，只减 `stock_locked`，普通可售库存增加，秒杀 Redis 不变。

| 订单类型 | 调用链 | 涉及的库存口径 |
|---|---|---|
| 秒杀订单 | order → seckill → ware | `stock_locked`、`seckill_stock_locked`、秒杀 Redis |
| 普通订单 | order → ware | `stock_locked`、普通库存缓存 |

### 异常与降级

- seckill 不可用：`SeckillFeignClientFallback` 返回错误码，order 只记日志，取消仍成功，等待对账补释放。
- 场次锁冲突：seckill 抛 14010，order 捕获并记日志，释放延后到对账任务。
- ware 秒杀释放失败：事务回滚，seckill 返回失败，order 只记日志；普通释放失败由延时消息和兜底任务重试。
- Redis 库存 key 不存在：`releaseReservation` 返回 `-1`，不修改 Redis，库存留在 `seckill_stock_locked` 等结算处理。
- 取消接口重复提交：订单状态、工作单状态和 Redis 标记共同保证不会重复加减库存。

## 三、执行顺序

1. `LoginUserInterceptor#preHandle`：从共享 Session 取登录会员放入 ThreadLocal，未登录 302 到登录页。
2. `PayController#cancel`：接收 `orderSn`，调用 `OrderServiceImpl#cancelOrder`，成功后调用 `AlipayService#closeTradeQuietly`。
3. `OrderServiceImpl#cancelOrder`：校验订单号与登录态，按 `order_sn` 查 `oms_order`。
4. 同上：订单不存在或 `member_id` 不匹配抛 9015；状态为 `4` 时重跑 `afterOrderClosed` 并返回。
5. 同上：状态不是 `0` 抛 9016；条件更新 `status 0→4`，条件为 `id` 与 `status=0`。
6. 同上：更新 0 行时重查；已被其它线程关闭则按幂等补释放，否则拒绝取消。
7. `OrderServiceImpl#afterOrderClosed`：`source_type=2` 调用 `SeckillFeignClient#releaseSeckillOrder`；其它订单调用 `releaseStockQuietly`。
8. `SeckillFeignClientFallback#releaseSeckillOrder`：seckill 不可用时返回错误码，order 只记日志，取消仍成功。
9. `SeckillOrderInternalController#release` → `SeckillOrderServiceImpl#releaseByOrderSn`：按 `order_sn` 查 `sms_seckill_order`；无记录返回 `null`，普通订单误调不报错。
10. 同上：状态不是 `BUILT` 时直接返回当前结果，重复取消幂等。
11. 同上：获取 `seckill:settle:lock:{sessionId}`，`tryLock` 3 秒；失败抛 14010，锁内重查状态。
12. `SeckillOrderServiceImpl#decideReleaseMode`：场次存在、有效状态为 `RUNNING`、库存 key 存在时返回 `RELEASE_TO_SECKILL`，否则返回 `RELEASE_TO_NORMAL`。
13. `WareFeignClient#releaseSeckillOrderStock` → `WareSkuServiceImpl#releaseSeckillOrderStock`：按 `order_sn` 查工作单；不存在直接返回，`biz_type` 非 1 抛错。
14. 同上：条件更新 `task_status 1→2` 抢占，0 行说明已释放，直接返回。
15. 同上：逐条明细把 `stock_locked` 减 `num`（要求足够），`SECKILL_POOL` 时把 `seckill_stock_locked` 加 `num`，明细 `lock_status 1→2`。
16. 同上：事务提交后调用 `refreshStockCache`，按数据库重算 `gulimall:ware:stock:{skuId}`。
17. `SeckillStockServiceImpl#releaseReservation`：仅 `SECKILL_POOL` 时执行 Lua，回补 `seckill:stock`、`seckill:user:count` 并写 `seckill:release`；`0` 已回补，`-1` key 不存在。
18. `SeckillOrderServiceImpl#releaseByOrderSn`：条件更新 `status 1→2`，写 `release_mode`、`release_reason`，返回结果并释放场次锁。
19. 普通分支：`WareFeignClient#releaseStockByOrderSn` → `StockReleaseExecutor#release`：按 `order_sn` 找工作单，获取 `gulimall:ware:stock:lock` 读锁后调用 `releaseStock`。
20. `WareSkuServiceImpl#releaseStock`：`biz_type=1` 跳过；条件更新 `task_status 1→2` 抢占；明细 `stock_locked` 减 `num`、`lock_status 1→2`。
21. 同上：事务提交后 `INCRBY gulimall:ware:stock:{skuId} num`，不修改 `stock`。
22. `AlipayService#closeTradeQuietly`：调用 `alipay.trade.close`，交易不存在、已支付或已关闭只记日志，不影响取消返回。
23. 异常分支：seckill 不可用或场次锁冲突时，order 只记日志，取消接口仍返回成功，等待对账任务补释放。
24. 异常分支：ware 秒杀释放失败时事务回滚，seckill 返回失败；普通释放失败由延时消息和定时兜底任务继续重试。
