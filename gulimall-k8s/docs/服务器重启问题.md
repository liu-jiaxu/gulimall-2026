### 服务器重启后网页 502：应用 Pod ImagePullBackOff

#### 现象

服务器重启后出现：

1. `https://k8s.gulimall.vip` 返回 502 Bad Gateway；
2. `kubectl -n gulimall-k8s get pods` 显示应用 Pod 为 `0/1 ImagePullBackOff`；
3. `kubectl -n gulimall-k8s get endpoints gulimall-k8s` 的 ENDPOINTS 为空；
4. `curl -I http://127.0.0.1:30080/` 返回 connection refused；
5. `journalctl -u cloudflared` 出现 `dial tcp 127.0.0.1:30080: connect: connection refused`；
6. MySQL、Redis、PVC、节点和 cloudflared 状态正常。

#### 原因

MySQL 和 Redis 的 StatefulSet 使用 `imagePullPolicy: IfNotPresent`，节点有缓存镜像时直接启动。应用 Deployment 使用 `imagePullPolicy: Always`，每次 Pod 重建都会强制从 Docker Hub 拉取镜像。服务器重启后，如果代理未开、Docker Hub 不可达、镜像 tag 不存在、仓库私有或触发限流，镜像拉取失败，Pod 进入 ImagePullBackOff。

Pod 没有 Ready，Service 的 Endpoints 为空，NodePort 30080 没有后端，cloudflared 连接 30080 被拒绝，Cloudflare 最终返回 502。

#### 诊断

> **命令说明：** 先确认 Pod 状态和 Service 的 Endpoints，判断 502 是因为应用没有 Ready，还是 Cloudflare Tunnel 本身的问题。

```bash
kubectl -n gulimall-k8s get pods
kubectl -n gulimall-k8s get endpoints gulimall-k8s
curl -I http://127.0.0.1:30080/
```

> **命令说明：** 查看 Pod 的事件，找到 Failed to pull image 的具体原因，例如 timeout、manifest unknown、401 或 toomanyrequests。

```bash
kubectl -n gulimall-k8s describe pod -l app=gulimall-k8s | tail -50
```

> **命令说明：** 读取 Deployment 当前使用的镜像 tag，并检查节点 containerd 是否已经缓存这个镜像。

```bash
kubectl -n gulimall-k8s get deployment gulimall-k8s -o jsonpath='{.spec.template.spec.containers[0].image}{"\n"}'
ctr -n k8s.io images ls | grep gulimall-k8s
```

常见错误：

| Events 错误 | 原因 | 处理 |
| --- | --- | --- |
| `i/o timeout` / `no such host` | 代理或网络不可用 | 开启代理，或改用内网镜像仓库 |
| `manifest unknown` / `not found` | 镜像 tag 不存在 | 重新执行 Jenkins 构建推送，或改成存在的 tag |
| `401 unauthorized` | Docker Hub 仓库私有 | 仓库改成 Public，或创建 imagePullSecret |
| `toomanyrequests` | Docker Hub 匿名拉取限流 | 使用 Docker Hub 账号创建 imagePullSecret，或稍后重试 |

#### 修复：镜像已缓存时使用 IfNotPresent

> **命令说明：** 节点已经缓存应用镜像时，把 Deployment 的 imagePullPolicy 改成 IfNotPresent，让 Pod 直接使用缓存，不再强制访问 Docker Hub。

```bash
kubectl -n gulimall-k8s patch deployment gulimall-k8s -p \
  '{"spec":{"template":{"spec":{"containers":[{"name":"app","imagePullPolicy":"IfNotPresent"}]}}}}'
```

> **命令说明：** 等待新的 Pod 启动并 Ready，确认滚动发布完成。

```bash
kubectl -n gulimall-k8s rollout status deployment/gulimall-k8s --timeout=180s
```

> **命令说明：** 确认 Service 已经挂上 Pod IP，并测试 NodePort 和公网访问是否恢复。

```bash
kubectl -n gulimall-k8s get endpoints gulimall-k8s
curl -I http://127.0.0.1:30080/
curl -I https://k8s.gulimall.vip/
```

修复成功时：

- 新的应用 Pod 为 `1/1 Running`；
- Endpoints 显示类似 `10.244.0.x:18080`；
- 本地 30080 返回 200 或 302；
- `https://k8s.gulimall.vip` 返回 200 或 302。

#### 永久修改

> **命令说明：** 上面的 patch 是临时操作。Jenkins 下次执行 `kubectl apply -f k8s/30-app.yaml` 时会把策略恢复成 Always。需要长期生效时，把 `30-app.yaml` 中应用容器的 `imagePullPolicy` 改成 IfNotPresent。

```yaml
containers:
  - name: app
    image: liujiaxucn/gulimall-k8s:latest
    imagePullPolicy: IfNotPresent
```

> 说明：如果镜像没有缓存，第一次仍需要网络或代理拉取；拉取成功后再使用 IfNotPresent，后续重启不再访问 Docker Hub。也可以改用内网镜像仓库，彻底摆脱 Docker Hub 和代理依赖。
