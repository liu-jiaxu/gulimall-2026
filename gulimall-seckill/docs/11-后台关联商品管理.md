# 业务流程 11：后台关联商品管理

## 一、设计思路

- 关联维护只允许在启用且未开始的场次进行，开始后库存和价格不再可改，避免活动进行中变更。
- 秒杀库存锁定到具体仓库：只增加 `wms_ware_sku.seckill_stock_locked`，不动 `stock` 和 `stock_locked`，实际仓库 id 回写关联表，后续增减和释放只针对该仓。
- 同一 SKU 禁止参加时间重叠的启用场次，因为 `seckill_stock_locked` 以“SKU + 仓库”聚合，无法按场次拆分释放。
- 场次级 Redisson 锁 `seckill:settle:lock:{sessionId}` 与停止、结算、取消、下架、删除共用，关联变更串行执行。
- coupon 与 ware 的跨库修改由 `@GlobalTransactional` 加本地事务保证；Redis 不在 Seata 内，由控制器在 `finally` 中清理或按旧快照恢复。
- ware 侧用 `operationId` 加 `wms_seckill_stock_operation` 唯一索引和 `INSERT IGNORE` 做幂等，条件更新保证可用库存不为负。
- 关联表用 `version` 乐观锁，修改和删除都带版本条件；`uk_session_sku` 在数据库层兜底重复关联。
- 提交成功后让 seckill 服务重建商品 Hash，并按数据库重算普通可售库存缓存 `gulimall:ware:stock:{skuId}`；刷新失败只记日志，由定时任务兜底。

## 二、主要功能描述

**触发动作**

- 后台秒杀场次页打开“关联商品”弹窗，执行新增、修改、删除或只读查询。
- 新增绑定 SKU 并锁定秒杀库存；修改可改价格、总量、限购、排序，也可换商品或换场次；删除按场次状态决定是否释放库存。

**前置条件**

- 场次存在、`status = 1`，且按存储状态和时间计算出的有效状态为未开始。
- SKU 可用库存满足 `stock - stock_locked - seckill_stock_locked >= 秒杀总量`。
- 同场次同 SKU 无重复关联，且该 SKU 未参加时间重叠的其他启用场次。

**做什么**

- 新增：校验后调 ware 选仓锁库存，写关联表、写 `seckill:stock:{sessionId}:{skuId}`，刷新商品 Hash 和普通库存缓存。
- 修改：换商品时释放旧 SKU 旧仓再锁新 SKU；不换商品时按数量差额在原仓加减；换场次时迁移 Redis key 和 Hash 字段。
- 删除：未开始场次释放库存；已结束或已取消场次只删记录；进行中和停止中拒绝删除。

**不做什么**

- 不扣减 `stock`，不创建订单，不发送 MQ。
- 不修改场次时间或状态，不重置已售数量和限购计数。
- 不自动换仓：调大数量只在原仓库加，原仓不足直接失败。

**操作与数据变化**

| 操作 | 库存动作 | 关联表 | Redis |
|---|---|---|---|
| 新增 | 新锁秒杀总量，自动选仓 | INSERT，写入 `ware_id`、`version=0` | SET stock key，成功后 HSET 商品 Hash |
| 改数量 | 只对原仓加/减差额 | UPDATE，`version+1` | 覆盖 stock key，刷新 Hash |
| 换商品 | 释放旧 SKU 旧仓，新 SKU 重新选仓 | UPDATE，`ware_id` 改为新仓 | DEL 旧 key 和旧字段，SET 新 key |
| 换场次 | 库存和仓库不动，数量变化仍按差额调整 | UPDATE，场次改为新场次 | 迁移 stock key 与 Hash 字段 |
| 删除 | 未开始释放，已结束/已取消不释放 | DELETE，带版本条件 | DEL stock key，HDEL Hash 字段 |
| 查询 | 不动库存 | 只读 | 只读数据库，商品名走 product |

**结果状态**

- 关联表写入 `ware_id` 和 `version`；秒杀库存 key、商品 Hash 与数据库一致；普通可售库存缓存按数据库重算。
- 操作失败时数据库回滚，控制器删除新写入的 key，并按旧快照恢复旧 key 和旧 Hash 字段。

## 三、执行顺序

1. `SeckillSkuRelationController#save`：按 `promotionSessionId` 获取 `seckill:settle:lock:{sessionId}` Redisson 锁，最多等 3 秒。
2. `SeckillSkuRelationController#save`：调用 `saveRelation`；业务异常转 `R.error`，成功返回 `R.ok`。
3. `SeckillSkuRelationServiceImpl#saveRelation`：校验场次、SKU、数量必填，读 `sms_seckill_session` 确认启用且未开始。
4. `saveRelation`：按场次和 SKU 查重，再调用 `checkNoOverlappingSession` 检查时间重叠。
5. `saveRelation`：调用 `reserveAndGetWareId` 生成 `operationId`，调 ware `/ware/waresku/seckill/lock`，`wareId=0` 表示自动选仓。
6. `WareSkuServiceImpl#reserveSeckillStock`：校验参数，查 `wms_seckill_stock_operation`，同一 `operationId` 已锁定则直接返回原仓库。
7. `WareSkuServiceImpl#reserveSeckillStock`：选可用库存最多的仓库，`INSERT IGNORE` 写 LOCK 记录，条件更新 `seckill_stock_locked += quantity` 并返回 `ware_id`。
8. `saveRelation`：回填 `wareId`、`version=0`，INSERT `sms_seckill_sku_relation`；唯一键冲突转“已经关联过这个商品”。
9. `SeckillSkuRelationServiceImpl#writeSeckillStock`：SET `seckill:stock:{sessionId}:{skuId}` 为秒杀总量，TTL 到 `end_time + 1 天`。
10. `SeckillSkuRelationController#save` 的 `finally`：失败调用 `clearSeckillStock` 删除可能写入的 key；成功调用 `refreshSkuCache`。
11. `SeckillSkuServiceImpl#refreshSessionSku`：读场次和关联，查 product，沿用旧 `randomCode`，HSET `seckill:session:{sessionId}:skus` 并设置 TTL。
12. `SeckillSkuRelationController#save` 的 `finally`：调用 `refreshNormalStock` 让 ware 重算并写 `gulimall:ware:stock:{skuId}`，最后释放场次锁。
13. `SeckillSkuRelationController#update`：先读旧关联快照，记录旧场次、旧 SKU、旧数量和旧仓库，同时锁定旧场次和新场次。
14. `SeckillSkuRelationServiceImpl#updateRelation`：缺失字段用旧值兜底，校验新旧场次都未开始；换商品或换场次时重新查重并检查时间重叠。
15. `updateRelation` 分支：换商品时先 `release` 旧 SKU 旧仓的旧数量，再给新 SKU 重新选仓锁新数量。
16. `updateRelation` 分支：未换商品时按新数量减旧数量的差额，在原仓调用 `reserveOnWare` 或 `release`，`ware_id` 强制沿用旧值。
17. `updateRelation`：带 `version` 条件 UPDATE 关联表并将 `version+1`；影响 0 行提示“关联已被别人修改”。
18. `updateRelation`：换场次或换商品时删除旧 stock key、HDEL 旧 Hash 字段，再写新场次或新 SKU 的 key。
19. `SeckillSkuRelationController#update` 的 `finally`：失败删除新 key、按旧快照恢复旧 key、重建旧 Hash；成功刷新最终生效记录的 Hash；新旧 SKU 都刷新普通库存缓存并释放锁。
20. `SeckillSkuRelationController#delete`：先按 id 查出关联及涉及场次，锁定所有场次。
21. `SeckillSkuRelationServiceImpl#deleteRelations`：进行中或停止中拒绝；已结束或已取消只删记录；未开始及下架未结算的加入待释放列表。
22. `deleteRelations`：对每条待释放关联调用 `release` 扣减 `seckill_stock_locked`，再按 `version` 条件删除关联记录。
23. `deleteRelations`：DEL 对应 stock key、HDEL 商品 Hash 字段；Redis 异常只记日志，不影响删除结果。
24. `SeckillSkuRelationController#delete` 的 `finally`：无论成败刷新涉及 SKU 的普通库存缓存并释放场次锁。
25. `SeckillSkuRelationController#list/listBySession/listAll/info`：只读数据库，商品名称和图片走 product Feign，不写库、不碰 Redis。
