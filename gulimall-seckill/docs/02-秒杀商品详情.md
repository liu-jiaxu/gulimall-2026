# 业务流程 02：秒杀商品详情

## 一、设计思路

- 商品详情仍由 product 的 `item.html` 渲染，只有 URL 带 `seckillSessionId` 时才进入秒杀模式，普通商品页逻辑不受影响。
- 秒杀价格、限购、已购、剩余全部由 seckill 提供，product 不使用 URL 参数中的价格或数量，避免被篡改。
- product 通过 Feign 调 `/seckill/sku/info`，`FeignCookieConfig` 转发浏览器 Cookie，使 seckill 能读取共享 Session 中的会员。
- 接口允许游客访问；游客 `memberId` 为空，已购按 0 处理，登录用户才读取本人已购数量。
- `seckillSkuInfo` 受 Sentinel 保护：全局 200 QPS，单 `skuId` 热点 20 次/秒；被限流返回 14013，内部异常返回 14009。
- 商品快照优先读 Redis Hash，缺失时回源 `sms_seckill_session`、`sms_seckill_sku_relation` 与 product，并回填 Hash。
- 库存 key 只读，缺失按 0 并记录告警，不创建、不扣减；可购上限只是查询时的快照，不预占库存。
- product 捕获所有秒杀查询异常，静默退化为普通商品页，保证商品主体信息始终可访问。

## 二、主要功能描述

**触发动作**：在秒杀页点击商品卡片，打开 `item.html?skuId=...&seckillSessionId=...`。

**前置条件**：product 与 seckill 均已启动并注册 Nacos；共享 Session 配置一致；秒杀商品存在于 Hash，或能由数据库与 product 回源。

**流程职责**：
- 查询商品主体信息、图片、属性与库存。
- 查询购物车数量，失败时按空购物车处理。
- 有场次参数时查询秒杀信息，计算可购数量。
- 渲染秒杀价、划线原价、限购、已购、剩余。
- 限制数量输入，并处理“立即抢购”的登录跳转与回跳。

**不包含**：
- 不强制登录，游客可打开详情页。
- 不扣减或锁定库存。
- 不创建订单、不发送 MQ。
- 不校验场次是否开始、结束或停止。
- product 侧不做秒杀限流。

**结果**：
- seckill 正常：页面进入秒杀模式，显示秒杀价与可购上限。
- seckill 不可用或返回非 0 码：页面退化为普通商品页。
- 未登录点击抢购：跳 auth 登录页，登录后回到确认页。

**异常与降级**：
- seckill 未启动或超时：`loadSeckillSku` 返回 null，页面按普通商品处理。
- Sentinel 限流或方法异常：返回 14013 或 14009，product 同样退化为普通商品页。
- 商品 Hash 缺失或损坏：`loadSkuFromDb` 回源数据库与 product，成功后可恢复秒杀模式。
- 库存 key 缺失：`stock=0`，页面显示已抢光，但不会创建库存 key。
- 限购 Hash 缺失：`bought=0`，最终由提交接口再次校验限购。

**展示字段**：
- 秒杀价来自商品 Hash 的 `seckillPrice`，原价来自 product 的 `price`。
- 可购上限等于限购剩余与剩余库存中的较小值。

**数据与缓存**：
- `gulimall_pms`：product 商品主体只读。
- `sms_seckill_session`、`sms_seckill_sku_relation`：仅商品 Hash 回源时读取。
- `seckill:session:{sessionId}:skus`：读商品快照，回源时写入。
- `seckill:stock:{sessionId}:{skuId}`：只读剩余库存。
- `seckill:user:count:{sessionId}:{skuId}`：只读当前会员已购数量。

## 三、执行顺序

1. Nginx：`GET /item.html` 命中 `gulimall.vip` 站点，转发到 `gulimall-product:10000`。
2. `ItemController#skuItem`：接收 `skuId`、`seckillSessionId`、Session 与 Model。
3. `SkuInfoServiceImpl#item`：查询 product 商品主体、图片、属性与库存。
4. `ItemController#cartItems`：调用购物车服务；异常时返回空列表，不影响页面。
5. `seckillSessionId != null`：调用 `ItemController#loadSeckillSku`。
6. `SeckillFeignClient#getSkuInfo`：请求 seckill 的 `/seckill/sku/info`，参数为 `sessionId`、`skuId`。
7. `FeignCookieConfig`：把当前请求的 `Cookie` 头写入 Feign 请求，供 seckill 读取共享 Session。
8. `LoginUserInterceptor`：`/seckill/sku/info` 在放行列表，不强制登录。
9. `SeckillController#skuInfo`：进入 `@SentinelResource("seckillSkuInfo")` 方法。
10. Sentinel 拦截：全局 200 QPS 或单 `skuId` 20 次/秒超限，走 `skuInfoBlocked` 返回 14013。
11. 方法内部异常：走 `skuInfoFallback` 返回 14009，不把 500 抛给 product。
12. `SeckillSkuServiceImpl#getSkuInfo`：从共享 Session 取会员，游客 `memberId` 为 null。
13. 读 `HGET seckill:session:{sessionId}:skus {skuId}`；字段缺失、解析失败或 Redis 异常时进入回源。
14. `SeckillSkuServiceImpl#loadSkuFromDb`：查场次、查关联表、调 product。
15. `SeckillSkuServiceImpl#buildSkuVo` 与 `cacheSku`：组装 VO 并回填 Hash，TTL 为场次结束加 1 天。
16. 读 `seckill:stock:{sessionId}:{skuId}`：缺失或异常按 0，记录告警，不创建 key。
17. 读 `seckill:user:count:{sessionId}:{skuId}` 的会员 field：无值按 0；游客不读取。
18. 组装 `SeckillSkuInfoVo`（sku、stock、bought、limit），其中 `limit` 为空时按 1。
19. `ItemController#skuItem`：计算 `seckillMaxQuantity = min(max(limit-bought,0), max(stock,0))`。
20. product 收到非 0 码或 Feign 异常：`loadSeckillSku` 返回 null，页面退化为普通商品页。
21. Thymeleaf：`seckillSku != null` 时渲染秒杀价、划线原价、限购、已购、剩余、数量上限和“立即抢购”。
22. 页面 JS：`+` 不超过 `seckillMax`，`-` 不小于 1；抢购前再次校验数量。
23. 未登录点击抢购：跳 `auth.gulimall.vip/login.html?returnUrl=<确认页地址>`。
24. `LoginController#login`：登录成功后写共享 Session，`isSafeReturnUrl` 校验白名单。
25. `LoginRedirectService#afterLogin`：有默认地址直接回确认页，无默认地址先去个人中心；随后进入流程 03。
