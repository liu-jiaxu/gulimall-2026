# 业务流程 03：秒杀确认页

## 一、设计思路

- 确认页由 seckill 服务端渲染，`seckill.gulimall.vip` 经 Nginx 直连 14000，不经过网关。
- 拦截器放行 `/confirm.html`，页面内自行检查登录；未登录 302 到 auth 登录页，并携带编码后的 `returnUrl`。
- 商品信息复用 `getSkuInfo`，只读商品 Hash、库存与限购；Hash 缺失时回源数据库与 product 并回填。
- 只使用默认收货地址，不提供地址选择；无默认地址时跳个人中心，带 `needAddress=1` 和 `returnUrl`。
- 数量上限取 `min(limit - bought, stock)`，URL 中的 `num` 收敛到合法区间，避免负数或超过上限。
- `requestId` 在页面加载时生成，供流程 04 做幂等；`randomCode` 由服务端下发，提交时原样回传。
- 确认页只读：不扣库存、不写业务表、不发 MQ；场次开始与结束的校验留给提交接口。
- 地址查询异常按“无默认地址”处理，与登录回跳时地址异常放行的策略不同。

## 二、主要功能描述

**触发动作**：在详情页秒杀模式点击“立即抢购”，打开 `confirm.html?sessionId=...&skuId=...&num=...`。

**前置条件**：已登录；共享 Session 可读；商品 Hash 存在或可回源；会员至少有一条 `default_status=1` 的收货地址。

**流程职责**：
- 校验登录态，决定是否跳登录页。
- 加载商品、剩余库存、当前会员已购数量与每人限购。
- 加载并展示默认收货地址。
- 计算可购数量，收敛 URL 中的 `num`。
- 渲染确认页，生成 `requestId`，准备提交。

**不包含**：
- 不允许选择地址，只使用默认地址。
- 不扣减 Redis 库存，不创建 `sms_seckill_order`，不写 `mq_message`。
- 不校验场次开始、结束或停止状态。
- 不校验 `addrId` 是否属于当前会员。

**结果**：
- 正常：渲染 `seckill-confirm.html`，显示商品、默认地址、数量与提交按钮。
- 无默认地址：跳个人中心设置地址，设置完成后回跳确认页。
- 商品不存在：回到秒杀页。

**异常与降级**：
- 未登录：302 到 auth 登录页，登录成功后回到确认页。
- member 地址接口异常：按无默认地址处理，跳个人中心。
- Redis 商品 Hash 异常或缺失：回源数据库与 product；仍查不到时回秒杀页。
- 库存 key 缺失：`stock=0`，可购数量为 0，页面提示不可购买，不创建 key。
- 数量非法：`num` 小于 1 收敛到 1，超过上限收敛到上限。

**页面字段**：
- `info` 提供商品、限购、已购、剩余与随机码。
- `maxQuantity` 与 `quantity` 控制数量输入框的上下限。

**数据与缓存**：
- `sms_seckill_session`、`sms_seckill_sku_relation`：仅商品 Hash 回源时读取。
- `ums_member_receive_address`：member 服务按 `member_id` 只读。
- `seckill:session:{sessionId}:skus`：读商品快照，回源时写入。
- `seckill:stock:{sessionId}:{skuId}`、`seckill:user:count:{sessionId}:{skuId}`：只读。
- `seckill:req:*`、`seckill:reserve:*`：确认页不读不写，由流程 04 写入。

## 三、执行顺序

1. Nginx：`GET /confirm.html` 命中秒杀站点，转发到 `gulimall-seckill:14000`。
2. `LoginUserInterceptor`：`/confirm.html` 在放行列表，不拦截，登录检查交给控制器。
3. `SeckillPageController#confirmPage`：接收 `sessionId`、`skuId`、`num`、Session 与 Model。
4. 从共享 Session 取 `LOGIN_USER`；为空时拼确认页地址并 302 到 auth 登录页。
5. `SeckillSkuServiceImpl#getSkuInfo`：读取商品、库存、已购、限购。
6. 读 `HGET seckill:session:{sessionId}:skus {skuId}`；缺失或解析失败进入 `loadSkuFromDb`。
7. `loadSkuFromDb`：查 `sms_seckill_session`、`sms_seckill_sku_relation`，再调 `ProductFeignClient#getSkuInfo`。
8. `buildSkuVo` 与 `cacheSku`：组装 VO 并回填 Hash，TTL 为场次结束加 1 天。
9. 读 `seckill:stock:{sessionId}:{skuId}`：缺失或异常按 0，记录告警，不创建 key。
10. 读 `seckill:user:count:{sessionId}:{skuId}` 的会员 field：无值按 0。
11. 商品为空：302 回 `/seckill.html`。
12. `MemberFeignClient#getAddress`：调 member 的 `/member/memberreceiveaddress/{memberId}/address`。
13. `MemberReceiveAddressServiceImpl#getAddress`：按 `member_id` 查 `ums_member_receive_address`，`default_status DESC, id DESC`。
14. `confirmPage` 筛选 `defaultStatus == 1` 的第一条；无结果时 302 到个人中心。
15. 个人中心跳转参数带 `needAddress=1` 与编码后的确认页地址 `returnUrl`。
16. member 查询异常：捕获后按无默认地址处理，同样跳个人中心。
17. 计算 `max = min(max(limit-bought,0), max(stock,0))`。
18. 计算 `quantity = max(1, min(num, max(max,1)))`：超上限收敛到 `max`，小于 1 收敛到 1。
19. 把 `info`、`defaultAddress`、`quantity`、`maxQuantity`、`orderUrl`、`member` 放入 Model。
20. 返回视图 `seckill-confirm`，Thymeleaf 渲染商品、默认地址、数量输入与提交按钮。
21. `maxQuantity <= 0`：页面提示不可购买；提交前 JS 校验 `addrId` 与数量。
22. 页面 JS：生成一次性 `requestId`，与 `sessionId`、`skuId`、`randomCode` 等一起准备提交。
23. 登录与地址回跳链路：auth 登录，检查地址，个人中心设置默认地址，再回跳确认页。
24. `LoginController#login`：登录成功后写共享 Session，`isSafeReturnUrl` 校验白名单。
25. 点击提交：浏览器 `POST /seckill/order/submit`，进入流程 04。
