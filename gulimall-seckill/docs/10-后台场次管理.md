# 业务流程 10：后台场次管理

## 一、设计思路

- 场次有两个独立字段：`status` 表示启用或下架，`seckill_state` 表示 `0` 未开始、`1` 进行中、`2` 停止中、`3` 已结束、`4` 已取消。
- 有效状态按“人工状态优先、时间兜底”计算：`2/3/4` 直接返回，`0/1` 根据 `start_time`、`end_time` 实时判断，避免定时任务漏跑导致状态不准。
- 到点开始和结束不靠扫表，使用可靠消息表加延迟交换机发送 `seckill.start`、`seckill.end`；消息带期望时间戳，时间被修改后旧消息会被忽略。
- 新增和修改强制 `seckill_state=0`；新增固定 `status=1`，修改保留旧 `status`，从写入口防止绕过状态机。
- 取消只允许进行中：先进入停止中并写 `settle_type=2`、`stop_time=now`，删除库存 key 阻止继续抢购，再按宽限期发 `seckill.settle`。
- 删除是物理删除：已结束或已取消直接删；未结算的未开始场次先调用 ware 释放数据库剩余的活动锁定，避免库存长期占用。
- 下架只改 `status=0` 并删除商品 Hash，不释放库存、不删库存 key、不发 MQ，库存要等删除场次才释放。
- 下架、取消、删除、结算和关联修改共用场次锁 `seckill:settle:lock:{sessionId}`，防止判断进行中与结算删 key 交叉。

状态字段：`seckill_state` 的 `2` 停止中需要宽限期结算，`settle_type` 决定最终进入 `3` 已结束还是 `4` 已取消。
关键键：`seckill:settle:lock:{sessionId}`、`seckill:stock:{sessionId}:{skuId}`、`seckill:session:{id}:skus`。

## 二、主要功能描述

### 触发与前置

- 触发：renren-fast-vue 的秒杀场次页面调用 `list`、`info`、`save`、`update`、`offline`、`cancel`、`delete`。
- 前置：coupon 服务可访问 `gulimall_sms`、Redis、RabbitMQ；后台具备对应 Shiro 权限；开始和结束时间合法；取消要求进行中；删除不允许进行中或停止中。

### 处理内容

- 新增：写 `sms_seckill_session`，状态固定未开始、启用固定 1，发开始和结束两条延时消息。
- 修改：只允许未开始场次；补全缺失时间、保留状态字段、校验同 SKU 时间重叠，重新发开始和结束消息。
- 下架：仅把 `status` 改为 0 并删除 `seckill:session:{id}:skus`。
- 取消：进行中改停止中，删库存 key，按 `graceMs` 发结算消息，最终由结算改成已取消。
- 删除：校验状态，未结算场次先释放 ware 剩余锁定，再删关联、场次和 Redis key，刷新普通库存缓存。

### 不处理内容

- 不管理场次下的关联商品，不展开到点开始、到点结束和结算的完整释放逻辑。
- 下架不释放库存，删除不发 MQ，已投递的旧消息由消费者按状态或时间自行忽略。
- 不做秒杀订单退款和取消，订单侧由取消、超时和支付流程处理。

### 最终结果

- 新增：DB 多一条 `status=1`、`seckill_state=0` 的场次，`mq_message` 多两条消息。
- 修改：时间、名称、活动更新，重新生成开始和结束消息；旧消息不撤回但会被忽略。
- 下架：`status=0`，商品 Hash 删除，库存锁定保留。
- 取消：`seckill_state` 先变 2，宽限期后变 4，库存 key 删除。
- 删除：场次和关联记录消失，未结算库存释放，Redis 库存、限购和商品 Hash 清理。

### 异常与降级

- 新增时 `status` 选未启用：后端强制 1，页面单选框不生效。
- 修改已开始或已结束场次：`effectiveState` 非未开始，直接拒绝修改。
- 新增不检查同 SKU 重叠：只有修改会调用重叠校验。
- 下架进行中或停止中：拒绝；下架未开始场次不释放库存。
- 删除进行中、停止中或到点未结算：拒绝；批量删除中途失败不回滚已删记录。

## 三、执行顺序

1. `SeckillSessionController#list`：调用 `SeckillSessionServiceImpl#queryPage` 分页查询 `sms_seckill_session`，不消费 `key` 参数。
2. `SeckillSessionController#info`：按 id 返回场次，供修改弹窗回填。
3. `SeckillSessionController#save` → `SeckillSessionServiceImpl#saveSession`：事务内调用 `validateTime` 校验开始、结束非空且结束晚于开始。
4. 同上：强制 `seckill_state=0`、`status=1`，创建时间缺失时补当前时间，插入场次。
5. `SeckillSessionServiceImpl#sendStartMessage`：`status=1` 时按 `start_time-now` 计算延迟，写 `mq_message` 并投递 `seckill.start`。
6. `SeckillSessionServiceImpl#sendEndMessage`：`status=1` 时按 `end_time-now` 计算延迟，写 `mq_message` 并投递 `seckill.end`。
7. `SeckillSessionController#update` → `SeckillSessionServiceImpl#updateSession`：查旧场次，`effectiveState` 不是未开始时拒绝修改。
8. 同上：缺失时间用旧值，`seckill_state`、`status`、`create_time` 保留旧值，校验时间合法。
9. `SeckillSessionServiceImpl#checkNoOverlappingSession`：查本场次关联 SKU，再查同 SKU 其它启用场次，时间区间相交则抛异常。
10. 同上：`updateById` 更新场次，重新调用 `sendStartMessage` 和 `sendEndMessage`。
11. `SeckillSessionState#effectiveState`：`2/3/4` 直接返回，其余按当前时间与开始、结束时间返回 `0/1/3`。
12. `SeckillSessionController#offline` → `SeckillSettleServiceImpl#offlineSession`：获取场次锁，查场次；`status=0` 直接返回。
13. 同上：仅有效状态为未开始、或已结束、或已取消时允许下架。
14. 同上：条件更新 `status 1→0`，删除 `seckill:session:{id}:skus`；不释放库存、不发 MQ。
15. `SeckillSessionController#cancel` → `SeckillSettleServiceImpl#cancelSession`：获取场次锁，在事务内调用 `doCancel`。
16. `SeckillSettleServiceImpl#doCancel`：已取消幂等返回；停止中或已结束拒绝；`status` 非 1 或有效状态非进行中拒绝。
17. 同上：条件更新 `seckill_state=2`、`settle_type=2`、`stop_time=now`；0 行时已是停止中且最终取消则幂等返回。
18. 同上：`deleteStockKeys` 删除 `seckill:stock:{sessionId}:{skuId}`，按 `graceMs` 发送 `seckill.settle`。
19. `SeckillSessionController#delete` → `SeckillSettleServiceImpl#deleteSessions`：逐个调用 `deleteOneSession`，批量删除没有整体事务。
20. `SeckillSettleServiceImpl#deleteOneSession`：获取场次锁，查场次；进行中、停止中、到点未结算均拒绝。
21. 同上：未结算场次遍历关联，调用 `WareFeignClient#releaseRemainingSeckillStock`，`operationId` 由场次、关联和固定前缀组成。
22. 同上：物理删除 `sms_seckill_sku_relation` 和 `sms_seckill_session`。
23. 同上：删除 `seckill:stock`、`seckill:user:count`、`seckill:session:{id}:skus`，调用 `refreshStock` 刷新普通库存缓存。
24. `SeckillPromotionController#update` / `#delete` → `hasUnfinishedSessions`：活动下存在启用且未结束或未取消的场次时拒绝修改、删除活动。
25. 异常分支：下架、取消、删除拿不到场次锁时抛“正在处理中”；删除未结算场次时 ware 释放失败会中止删除，已删记录不回滚。
