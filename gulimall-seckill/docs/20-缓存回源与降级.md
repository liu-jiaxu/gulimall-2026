# 业务流程 20：缓存回源与降级

## 一、设计思路

- 三类数据放 Redis：商品展示快照、库存与限购、防重与幂等标记；全部 key 由 `SeckillConstant` 统一拼接，读写删除引用同一份规则。
- 商品 Hash `seckill:session:{sessionId}:skus` 可回源：缺失、读取异常或全部解析失败时，从场次表、关联表与 product 重建并尽量回填。
- 库存 String `seckill:stock:{sessionId}:{skuId}` 绝不凭空创建，只能由关联锁库存或上架 `setIfAbsent` 产生，避免无依据地造库存。
- 上架只补不覆盖：已存在的库存 key 可能已被扣减，`setIfAbsent` 保留当前剩余量，防止把库存重置回总量。
- 预扣与释放用 Lua 原子完成库存、限购、防重与预扣标识的校验和写入，避免并发下出现部分成功。
- 限购 Hash `seckill:user:count:{sessionId}:{skuId}` 与订单最终一致：预扣递增、释放递减，对账任务按待建单、已建单、已支付订单重建。
- 展示链路可降级，提交链路必须完整：提交时商品 Hash 缺失直接返回 `14011`，不回源。
- 场次锁由 Redisson 提供，让停止、结算、下架、删除、关联修改与取消订单互斥。

## 二、主要功能描述

**触发与前置**

- 触发来源：打开秒杀页、打开商品详情或确认页、提交抢购、后台关联变更、场次停止或结算、每日上架、对账任务。
- 前置条件：seckill 与 coupon 连接同一 Redis，读写同一批 `seckill:*` key。
- 关联商品需先在 ware 锁库存，库存 key 才会创建；商品名称、价格、图片来自 product。
- 场次、关联与秒杀订单存放在 `gulimall_sms` 的 `sms_seckill_session`、`sms_seckill_sku_relation`、`sms_seckill_order`。

**做什么**

- 商品 Hash：上架批量写入，回源时单条或整场回填，后台关联变更后按 SKU 刷新，场次结束或删除时清理。
- 库存 key：关联新增或改数量时写入总量，上架只补不覆盖，预扣递减、释放递增，停止、结算、删除场次时删除。
- 限购 Hash：预扣时按会员递增，释放时递减且不为负，对账任务按订单事实重建并保持与库存 key 一致的 TTL。
- 防重与幂等：`seckill:req:*` 让同会员同 SKU 在 10 秒内只受理一次，重复请求返回首次订单号；`seckill:reserve:*` 保留 30 分钟标记预扣，`seckill:release:*` 保留 7 天防止延迟消息重复回补。
- 场次锁：`seckill:settle:lock:{sessionId}` 由 Redisson 管理，拿不到锁时结算、下架直接返回，取消订单报 `14010`。
- 降级：Hash 缺失回源数据库与 product；库存 key 缺失时详情页显示 0 并告警、抢购返回 `14011`；product 不可用时跳过该 SKU。

**不做什么**

- 不在回源时创建库存 key，也不自动修复库存数据。
- 秒杀页不展示剩余库存，只有在详情页与确认页展示。
- 不做与数据库的强一致，商品信息变更依赖每日上架或手动刷新。
- 每日库存对账只记录告警，不修改 Redis。
- 不使用 hash tag，所有 key 按拼接结果落在默认槽位。

**结果**

- Hash 命中时直接展示，不查关联表与 product。
- Hash 缺失时页面仍可展示并回填，TTL 为场次结束加 1 天。
- 库存 key 缺失时详情页显示 0、提交返回 `14011`，不自动补 key。
- Redis 整体不可用时商品详情退普通商品页，抢购失败且不扣库存。

**数据变化**

- 商品 Hash：上架、回填、单 SKU 刷新写入；结算、下架、删除场次与关联变更时删除字段或整 key。
- 库存 key：关联写入总量，上架只补不覆盖，Lua 预扣递减、释放递增，停止与结算删除。
- 限购 Hash：Lua 递增递减，对账任务删除后重建。
- Redis 以 `seckill:*` key 为准，数据库提供回源依据与订单事实。
- ware 库存：关联锁库存、结算释放、取消释放都会调用 ware，普通库存缓存另行刷新。

**异常与边界**

- Hash 部分 JSON 损坏时只跳过坏数据，仍返回可解析商品，不整体回源。
- 库存 key 值不是数字时按 0 处理并告警，抢购返回 `14011`。
- 限购 Hash 缺失时已购按 0，存在约 1 分钟的重建窗口。
- Redis 不可用时展示链路回源或退普通页，提交链路直接失败且不扣库存。
- 释放时库存 key 已删除则不回补秒杀库存，订单转为普通池处理。
- 关联写库存 key 失败时事务回滚，避免数据库有库存而 Redis 没有。

## 三、执行顺序

1. `SeckillSkuScheduled#uploadSeckillSku`：每日 3 点触发商品上架。
2. `SeckillSkuServiceImpl#uploadSeckillSkuLatest3Days`：查询启用、未开始或进行中、且在未来 3 天内结束的场次。
3. `SeckillSkuServiceImpl#uploadSeckillSkuLatest3Days`：按场次读取 `sms_seckill_sku_relation`，逐个调用 product 获取 SKU 信息。
4. `SeckillSkuServiceImpl#buildSkuVo`：沿用旧 Hash 中的 `randomCode`，组装商品快照。
5. `SeckillSkuServiceImpl#uploadSeckillSkuLatest3Days`：用 `setIfAbsent` 补库存 key，不覆盖已有剩余量。
6. `SeckillSkuServiceImpl#uploadSeckillSkuLatest3Days`：`putAll` 写整场 Hash，并设置 TTL 为场次结束加 1 天。
7. `SeckillSkuRelationServiceImpl#writeSeckillStock`：关联新增或改数量时，ware 锁库存成功后用 `set` 写入新总量。
8. `SeckillPageController#seckillPage`：打开秒杀页，调用整场商品读取。
9. `SeckillSkuServiceImpl#getSessionSkus`：读取整场 Hash，异常或为空时转 `loadSessionSkusFromDb`。
10. `SeckillSkuServiceImpl#loadSessionSkusFromDb`：查场次、关联与 product 组装展示数据，并调用 `cacheSku` 逐条回填。
11. `SeckillSkuServiceImpl#refreshSessionSku`：关联变更后按场次与 SKU 刷新单个 Hash 字段，product 不可用时保留旧值。
12. `SeckillController#skuInfo`：详情请求读取单 SKU Hash，缺失时调用 `loadSkuFromDb` 回源并回填。
13. `SeckillSkuServiceImpl#getSkuInfo`：读库存 String 与限购 Hash；库存缺失记告警并返回 0，游客已购按 0。
14. `SeckillOrderController#submit`：提交抢购，读取 Hash 校验随机码、仓库、价格与时间窗口，缺失直接返回 `14011`。
15. `SeckillStockServiceImpl#tryReserve`：执行预扣 Lua，依次校验库存 key、时间窗口、防重 key、限购与库存。
16. `SeckillStockServiceImpl#tryReserve`：校验通过后扣库存、增限购、写防重 key 与预扣标识，返回剩余库存。
17. `SeckillOrderServiceImpl#submit`：预扣返回 1 落预扣单；返回 2 返回首次订单号；其余按返回码映射错误码。
18. `SeckillStockServiceImpl#release`：取消或失败回补时执行释放 Lua，检查释放标识与库存 key，回补库存并递减限购。
19. `SeckillOrderServiceImpl#decideReleaseMode`：场次仍在进行且库存 key 存在才回秒杀池，否则回普通可售池。
20. `SeckillLimitReconcileTask#reconcile`：每分钟按待建单、已建单、已支付订单重建限购 Hash。
21. `SeckillStockReconcileTask#reconcile`：每日 3 点检查库存 key 是否存在、值是否在有效区间，只记录告警。
22. `SeckillSettleServiceImpl#settle`：停止或结算时获取场次锁，删除库存、限购与整场 Hash，并刷新普通库存缓存。
