# 业务流程 16：秒杀活动管理

## 一、设计思路

- 活动是场次的归属标签，后台只维护 `sms_seckill_promotion` 一行；场次通过普通列 `promotion_id` 关联，没有外键、索引和级联，两者生命周期独立。
- 保护逻辑：活动下存在“启用且未结束”的场次时拒绝修改与删除，避免活动被停用或删除后场次和库存继续运行。
- 未结束判定由存储状态与时间共同决定：只有 `status=1` 的场次参与判断，`SeckillSessionState.effectiveState` 把存储状态与起止时间折算为有效状态，非 `ENDED(3)`、`CANCELLED(4)` 即视为未结束。
- 修改与删除采用全有或全无：批量删除中任一活动被保护就整体拒绝，不做部分删除。
- 持久化使用 MyBatis-Plus 默认实现：新增直接插入、修改只写非 null 字段、删除按主键物理删除；没有自动填充、版本号和逻辑删除。
- 列表分页不解析查询参数，`key` 不进入 SQL，查询框只影响前端展示。
- 活动自身的 `status`、`start_time`、`end_time` 不参与运行期判断，把状态改为 0 不会停止已存在的场次。
- 场次侧写入 `promotion_id` 时不校验目标活动是否存在、是否上线，活动与场次之间没有一致性约束。

## 二、主要功能描述

**触发与前置**

- 管理员在 renren-fast 后台的秒杀活动页面执行列表、新增、修改、删除。
- 请求以 `/gulimall/coupon/seckillpromotion/**` 进入网关，转发到 `gulimall-coupon`。
- 依赖 `sms_seckill_promotion`、`sms_seckill_session` 两张表，后台菜单需在运行库手工配置。
- 控制器方法带 `@RequiresPermissions`，但 `gulimall.shiro.enabled` 未开启，注解不产生拦截。

**做什么**

- 列表：分页查询 `sms_seckill_promotion`，无过滤条件、无排序。
- 详情：按 id 查单条，供修改弹窗回填；不存在时返回空对象。
- 新增：请求体直接插入，不校验标题、时间、状态；`create_time`、`user_id` 由调用方决定是否提交。
- 修改：先判断活动下是否有未结束场次，没有才更新，且只写非 null 字段。
- 删除：逐个判断活动，全部通过后按主键批量物理删除。
- 场次表单：读取活动列表作为“所属活动”下拉，保存时把 `promotionId` 写入场次。

**不做什么**

- 不级联修改或删除场次，不改库存、不写 Redis、不发 MQ。
- 不校验活动时间是否覆盖场次时间，不改场次状态。
- 不校验 `promotionId` 是否存在或已上线。
- 没有并发控制，保护判断与写入之间可以插入新场次。

**结果**

- 操作成功时活动表新增、更新或删除一行。
- 存在未结束场次时修改与删除返回 `R.error`，活动行不变；`status=0` 的场次与已结束、已取消场次不阻止操作。
- 删除活动后，其下已结束场次的 `promotion_id` 指向不存在的活动。

**数据变化**

- `sms_seckill_promotion`：列表与详情读取，新增插入，修改更新非 null 字段，删除物理删除。
- `sms_seckill_session`：保护判断按 `promotion_id` 只读，活动流程不写入场次。
- Redis 与 MQ：不读写，不触发场次开始、结束或结算消息。
- 删除活动后，已结束场次的 `promotion_id` 保留原值，形成悬空引用。

**异常与边界**

- 修改请求缺少 `id` 时同样返回“还有未结束场次”，错误信息指向保护而非参数缺失。
- 删除请求为空列表时会触发空指针，正常前端总会提交数组。
- 场次 `status=0` 时跳过保护，已下架但仍在进行的场次不会阻止活动删除。
- 场次时间字段为 null 时按存储状态判断，通常是未开始，会阻止操作。
- 活动不存在时详情返回 `code=0` 与 null，前端读取字段时报错。
- 保护判断与场次新增并发时没有锁，检查通过后仍可能创建新场次。

## 三、执行顺序

1. `seckill.vue#getDataList`：提交 `page`、`limit`、`key` 到 `/coupon/seckillpromotion/list`。
2. `SeckillPromotionController#list`：接收请求参数，调用 `queryPage`。
3. `SeckillPromotionServiceImpl#queryPage`：按分页查询 `sms_seckill_promotion`，无 WHERE、无排序。
4. `SeckillPromotionController#info`：按 id 调用 `getById`，结果放入 `seckillPromotion`。
5. `seckillpromotion-add-or-update.vue#init`：修改场景先调 `info` 回填表单，新增场景只准备空表单。
6. `seckillpromotion-add-or-update.vue#dataFormSubmit`：按 `id` 是否为空选择 `save` 或 `update`。
7. `SeckillPromotionController#save`：直接调用 `save` 插入 `sms_seckill_promotion`，无业务校验。
8. `SeckillPromotionController#update`：先判断 `id` 是否为空，再调用 `hasUnfinishedSessions`。
9. `SeckillPromotionController#hasUnfinishedSessions`：按 `promotion_id` 读取 `sms_seckill_session`。
10. `SeckillSessionState#effectiveState`：对 `status=1` 的场次折算有效状态，非 `ENDED`、`CANCELLED` 即返回 true。
11. `SeckillPromotionController#update`：保护命中返回 `R.error`，未命中调用 `updateById` 更新非 null 字段。
12. `seckill.vue#deleteHandle`：收集单条或批量 id，确认后提交到 `/delete`。
13. `SeckillPromotionController#delete`：遍历 id，逐个调用 `hasUnfinishedSessions`。
14. `SeckillPromotionController#delete`：任一活动被保护就整体返回 `R.error`，不执行删除。
15. `SeckillPromotionServiceImpl#removeByIds`：全部通过后按主键批量物理删除活动。
16. `seckillsession-add-or-update.vue#loadPromotions`：场次表单读取第 1 页 1000 条活动作为下拉。
17. `SeckillSessionServiceImpl#saveSession`：新场次固定 `seckill_state=0`、`status=1`，写入 `promotion_id` 并发送起止延时消息。
18. `SeckillSessionServiceImpl#updateSession`：未开始场次允许修改 `promotion_id`，只校验时间与 SKU 重叠，不校验目标活动。
