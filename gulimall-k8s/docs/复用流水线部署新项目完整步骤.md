# 复用流水线部署新项目完整步骤

## 一、适用范围

这份文档说明在现有 Kubernetes、Jenkins、Docker Hub 和凭据已经配置好的前提下，如何把一个新的 Java 服务接入现有流水线。

适用于：

1. 新的 Spring Boot 服务；
2. 新的 Maven 模块；
3. 独立仓库或当前仓库中的新目录；
4. 使用现有 Jenkins 凭据和 Kubernetes 命名空间。

环境本身的安装见《流水线环境配置与下载步骤》。

## 二、新项目接入清单

| 项目 | 是否必需 | 说明 |
| --- | --- | --- |
| Git 仓库 | 必需 | Jenkins 从 Git 拉取代码 |
| Maven pom.xml | 必需 | 能执行 `mvn clean package` |
| Dockerfile | 必需 | 把 jar 打成运行镜像 |
| Kubernetes Deployment | 必需 | 定义 Pod、镜像、端口、环境变量 |
| Kubernetes Service | 必需 | 为 Pod 提供稳定访问入口 |
| Secret / ConfigMap | 按需 | 数据库密码、Redis 密码、业务配置 |
| Jenkinsfile | 必需 | 描述构建、推送、部署步骤 |
| Docker Hub 公开仓库 | 必需 | 保存镜像 |
| Jenkins 凭据 | 复用 | `github-pat`、`dockerhub-credentials`、`kubeconfig-gulimall-k8s` |

## 三、准备 Dockerfile

> **命令说明：** Dockerfile 定义运行镜像。基础镜像使用 JRE 21，不把整套 JDK 带进运行镜像；创建固定 uid 的非 root 用户，复制 Maven 打好的 jar，设置时区和 JVM 容器参数。

```dockerfile
FROM eclipse-temurin:21-jre-jammy

RUN groupadd --gid 10001 app \
    && useradd --uid 10001 --gid 10001 --system --home-dir /app --shell /usr/sbin/nologin app

WORKDIR /app

# 把 jar 文件名替换成实际 Maven 产物
COPY target/gulimall-xxx-1.0.0.jar /app/app.jar

RUN chown -R app:app /app

USER 10001:10001

EXPOSE 8080

ENV TZ=Asia/Shanghai \
    JAVA_TOOL_OPTIONS="-XX:MaxRAMPercentage=75 -XX:MaxMetaspaceSize=192m -XX:ReservedCodeCacheSize=96m -Xss512k -Duser.timezone=Asia/Shanghai -Dfile.encoding=UTF-8"

ENTRYPOINT ["java", "-jar", "/app/app.jar"]
```

> **命令说明：** 构建镜像前先确认 Maven 已经生成 jar。`ls` 用于核对 jar 名称和 Dockerfile 中的 `COPY` 路径一致。

```bash
cd /opt/gulimall/gulimall-xxx
mvn -B clean package
ls -lh target/*.jar
```

> **命令说明：** 使用 Docker 构建运行镜像。Docker 守护进程已经配置代理，会通过代理拉取基础镜像。

```bash
docker build -t liujiaxucn/gulimall-xxx:manual-test .
docker images | grep gulimall-xxx
```

## 四、准备 Kubernetes 清单

> **命令说明：** Deployment 定义 Pod 的镜像、端口、环境变量、健康检查和资源限制。容器名 `app` 后面会被 Jenkinsfile 的 `kubectl set image` 使用。

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: gulimall-xxx
  namespace: gulimall-k8s
  labels:
    app: gulimall-xxx
spec:
  replicas: 1
  strategy:
    type: Recreate
  selector:
    matchLabels:
      app: gulimall-xxx
  template:
    metadata:
      labels:
        app: gulimall-xxx
    spec:
      securityContext:
        runAsNonRoot: true
        runAsUser: 10001
        runAsGroup: 10001
        fsGroup: 10001
      containers:
        - name: app
          image: liujiaxucn/gulimall-xxx:latest
          imagePullPolicy: Always
          ports:
            - name: http
              containerPort: 8080
          env:
            - name: TZ
              value: Asia/Shanghai
            - name: MYSQL_HOST
              value: mysql
            - name: MYSQL_PORT
              value: "3306"
            - name: MYSQL_DATABASE
              value: gulimall_k8s_ai
            - name: MYSQL_USERNAME
              value: root
            - name: MYSQL_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: gulimall-k8s-secrets
                  key: mysql-password
            - name: REDIS_HOST
              value: redis
            - name: REDIS_PORT
              value: "6379"
            - name: REDIS_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: gulimall-k8s-secrets
                  key: redis-password
          resources:
            requests:
              cpu: "100m"
              memory: "256Mi"
            limits:
              cpu: "500m"
              memory: "768Mi"
          startupProbe:
            httpGet:
              path: /actuator/health/liveness
              port: http
            failureThreshold: 30
            periodSeconds: 2
          readinessProbe:
            httpGet:
              path: /actuator/health/readiness
              port: http
            periodSeconds: 5
            failureThreshold: 3
          livenessProbe:
            httpGet:
              path: /actuator/health/liveness
              port: http
            periodSeconds: 10
            failureThreshold: 3
```

> **命令说明：** Service 为 Deployment 提供稳定的集群内地址。`selector` 必须和 Deployment 的 Pod 标签一致。

```yaml
apiVersion: v1
kind: Service
metadata:
  name: gulimall-xxx
  namespace: gulimall-k8s
spec:
  selector:
    app: gulimall-xxx
  ports:
    - name: http
      port: 8080
      targetPort: 8080
```

> **命令说明：** 新服务需要环境变量时，提前创建 Secret。密码和 Key 不写进 Deployment，也不提交到 Git。

```bash
kubectl -n gulimall-k8s create secret generic gulimall-xxx-secrets \
  --from-literal=mysql-password='<your-password>' \
  --from-literal=redis-password='<your-password>' \
  --dry-run=client -o yaml | kubectl apply -f -
```

> **命令说明：** 应用清单创建 Deployment 和 Service，然后查看 Pod 是否启动。

```bash
kubectl apply -f /opt/gulimall/gulimall-xxx/k8s/app.yaml
kubectl -n gulimall-k8s get deploy,pods,svc | grep gulimall-xxx
```

## 五、准备 Jenkinsfile

> **命令说明：** 下面是一份参数化 Jenkinsfile，同一个 Job 可以通过参数部署不同服务。`SERVICE` 是 Deployment 名，`MODULE_DIR` 是模块目录，`IMAGE_REPO` 是 Docker Hub 仓库，`MANIFEST` 是 k8s 清单路径。

```groovy
pipeline {
    agent any

    parameters {
        string(name: 'SERVICE', defaultValue: 'gulimall-xxx', description: 'Deployment 名称')
        string(name: 'MODULE_DIR', defaultValue: 'gulimall-xxx', description: 'Maven 模块目录')
        string(name: 'IMAGE_REPO', defaultValue: 'liujiaxucn/gulimall-xxx', description: 'Docker Hub 仓库')
        string(name: 'MANIFEST', defaultValue: 'gulimall-xxx/k8s/app.yaml', description: 'k8s 清单路径')
        string(name: 'CONTAINER_NAME', defaultValue: 'app', description: 'Deployment 容器名')
        string(name: 'K8S_NAMESPACE', defaultValue: 'gulimall-k8s', description: '命名空间')
    }

    environment {
        DOCKER_CREDENTIALS_ID = 'dockerhub-credentials'
        KUBECONFIG_CREDENTIALS_ID = 'kubeconfig-gulimall-k8s'
    }

    stages {
        stage('Checkout') {
            steps {
                checkout scm
                script {
                    env.IMAGE_TAG = "${env.BUILD_NUMBER}-${env.GIT_COMMIT ? env.GIT_COMMIT.take(7) : 'nogit'}"
                }
            }
        }

        stage('Maven Build') {
            steps {
                sh '''
                  set -e
                  cd "${MODULE_DIR}"
                  mvn -B clean package
                '''
            }
        }

        stage('Docker Build and Push') {
            steps {
                withCredentials([usernamePassword(
                    credentialsId: env.DOCKER_CREDENTIALS_ID,
                    usernameVariable: 'DOCKER_USER',
                    passwordVariable: 'DOCKER_PASS'
                )]) {
                    sh '''
                      set -e
                      echo "$DOCKER_PASS" | docker login -u "$DOCKER_USER" --password-stdin
                      docker build -t "${IMAGE_REPO}:${IMAGE_TAG}" -t "${IMAGE_REPO}:latest" "${MODULE_DIR}"
                      docker push "${IMAGE_REPO}:${IMAGE_TAG}"
                      docker push "${IMAGE_REPO}:latest"
                    '''
                }
            }
        }

        stage('Kubernetes Deploy') {
            steps {
                withCredentials([file(
                    credentialsId: env.KUBECONFIG_CREDENTIALS_ID,
                    variable: 'KUBECONFIG'
                )]) {
                    sh '''
                      set -e
                      kubectl -n "${K8S_NAMESPACE}" apply -f "${MANIFEST}"
                      kubectl -n "${K8S_NAMESPACE}" set image deployment/"${SERVICE}" "${CONTAINER_NAME}"="${IMAGE_REPO}:${IMAGE_TAG}"
                      kubectl -n "${K8S_NAMESPACE}" rollout status deployment/"${SERVICE}" --timeout=180s
                    '''
                }
            }
        }
    }

    post {
        always {
            sh 'docker logout || true'
        }
        success {
            echo "部署成功：${params.SERVICE} → ${params.IMAGE_REPO}:${env.IMAGE_TAG}"
        }
        failure {
            echo "流水线失败，查看 Jenkins 控制台、kubectl describe 和 kubectl logs"
        }
    }
}
```

> **命令说明：** 新服务加入 Git 后，先提交并推送。Jenkins 从这个分支拉取代码和 Jenkinsfile。

```cmd
cd /d D:\SoftwareInstallation\gulimall && git add gulimall-xxx && git commit -m "feat(gulimall-xxx):新增服务" && git push origin develop/gulimall/v0.1
```

## 六、创建 Jenkins 任务

> **命令说明：** 以下步骤在 Jenkins 页面操作。新版 Jenkins 的 Pipeline 配置在左侧「流水线」菜单。

```text
1. Jenkins 首页 → New Item / 新建任务
2. 名称：gulimall-xxx
3. 类型：Pipeline
4. 点击 OK
5. 左侧点击「流水线 / Pipeline」
6. Definition 选择 Pipeline script from SCM
7. SCM 选择 Git
8. Repository URL：https://github.com/liu-jiaxu/gulimall.git
9. Credentials：github-pat
10. Branch Specifier：*/develop/gulimall/v0.1
11. Script Path：gulimall-xxx/Jenkinsfile
12. 保存
```

> **命令说明：** 新服务需要独立的公开 Docker Hub 仓库。仓库不存在时先创建，否则 `docker push` 会失败。

```text
Docker Hub → Repositories → Create repository
Namespace: liujiaxucn
Repository name: gulimall-xxx
Visibility: Public
```

> **命令说明：** 第一次构建前确认 Jenkins 凭据已经存在：GitHub PAT、Docker Hub Token、kubeconfig。

```text
Manage Jenkins → Credentials → System → Global credentials (unrestricted)

github-pat
dockerhub-credentials
kubeconfig-gulimall-k8s
```

## 七、构建、验证和回滚

> **命令说明：** 在 Jenkins 任务页面点击 Build with Parameters，确认参数后开始构建。流水线会完成 Maven 构建、Docker 推送和 Kubernetes 发布。

```text
Jenkins → gulimall-xxx → Build with Parameters → Build
```

> **命令说明：** 构建结束后查看 Deployment、Pod、Service 和发布状态。

```bash
kubectl -n gulimall-k8s get deploy,pods,svc | grep gulimall-xxx
kubectl -n gulimall-k8s rollout status deployment/gulimall-xxx --timeout=180s
```

> **命令说明：** 查看应用日志，确认启动、数据库连接和业务异常。

```bash
kubectl -n gulimall-k8s logs -f deployment/gulimall-xxx
```

> **命令说明：** 如果新版本有问题，使用 rollout undo 回到上一个版本。

```bash
kubectl -n gulimall-k8s rollout history deployment/gulimall-xxx
kubectl -n gulimall-k8s rollout undo deployment/gulimall-xxx
kubectl -n gulimall-k8s rollout status deployment/gulimall-xxx --timeout=180s
```

## 八、多服务接入方式

> **命令说明：** 多个服务可以共用一份参数化 Jenkinsfile，通过 `SERVICE`、`MODULE_DIR`、`IMAGE_REPO`、`MANIFEST` 参数区分。每个服务仍然需要自己的 Dockerfile、k8s 清单和 Docker Hub 仓库。

```text
服务 A：SERVICE=gulimall-product，MODULE_DIR=gulimall-product，IMAGE_REPO=liujiaxucn/gulimall-product
服务 B：SERVICE=gulimall-order，MODULE_DIR=gulimall-order，IMAGE_REPO=liujiaxucn/gulimall-order
服务 C：SERVICE=gulimall-seckill，MODULE_DIR=gulimall-seckill，IMAGE_REPO=liujiaxucn/gulimall-seckill
```

> **命令说明：** 如果新服务放在新的 namespace，需要额外创建 ServiceAccount、Role、RoleBinding，并把 kubeconfig 的 namespace 改成新 namespace。

```bash
kubectl create namespace gulimall-new
kubectl -n gulimall-new create serviceaccount jenkins-deployer
kubectl -n gulimall-new create role jenkins-deployer --verb=get,list,watch,create,update,patch,delete --resource=deployments,services
kubectl -n gulimall-new create rolebinding jenkins-deployer --role=jenkins-deployer --serviceaccount=gulimall-new:jenkins-deployer
```

## 九、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `COPY failed` | Dockerfile 中的 jar 名称和 Maven 产物不一致 | `ls target/*.jar` 后修改 Dockerfile |
| `docker push denied` | Docker Hub 仓库不存在或 Token 没有写权限 | 创建公开仓库，Token 选择 Read & Write |
| `ImagePullBackOff` | 镜像名错误或仓库私有 | 确认镜像名、仓库公开、节点 containerd 代理 |
| `CrashLoopBackOff` | 数据库、Redis、环境变量或配置错误 | `kubectl logs`、`kubectl describe` |
| `rollout status` 超时 | 新 Pod 没有 Ready | 检查 probes、日志、资源限制 |
| `kubectl set image` 没生效 | Deployment 名或容器名写错 | 检查 `SERVICE` 和 `CONTAINER_NAME` 参数 |
| Jenkins 拉代码失败 | PAT 权限不足或代理未生效 | 使用 Classic PAT + `repo`，检查 Jenkins 代理 |

## 十、新项目上线检查表

| 检查项 | 确认方式 |
| --- | --- |
| Maven 能本地打包 | `mvn -B clean package` |
| Dockerfile 能构建 | `docker build -t 镜像:test .` |
| 镜像能推送 | `docker push` |
| k8s 清单能 apply | `kubectl apply -f` |
| Pod 能 Ready | `kubectl get pods` |
| 日志无异常 | `kubectl logs` |
| 服务能访问 | `kubectl get svc`、`curl` |
| 回滚可用 | `kubectl rollout undo` |
| Secret 不在 Git 中 | 检查仓库 |
| 资源限制和探针已配置 | 检查 Deployment |
