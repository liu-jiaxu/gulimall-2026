# 业务流程 18：监控与链路追踪

## 一、设计思路

- 采用 Micrometer Tracing 加 OTLP，把 span 统一发往 Jaeger；HTTP server span、Feign client span、定时任务 span 都由框架自动生成，没有手工埋点。
- 跨服务传播使用 W3C `traceparent`，同一请求在 gateway、seckill、product、order 等模块共享 traceId。
- tracing 依赖按模块单独引入，不放进 `gulimall-common`，未接入的模块不产生 span，也不承担上报开销。
- 采样为各服务本地概率采样，开发环境全量采集，生产按流量调低，采样率设为 0 时完全不导出。
- 定时任务自成根 trace，不与用户请求共享上下文；任务内部调用 Feign 时，client span 挂在任务 span 下。
- Jaeger 只负责链路存储与展示，不参与业务判断，Jaeger 不可用时接口正常返回。
- 观测分两套：Jaeger 看单条 trace，Sentinel Dashboard 看机器列表、资源 QPS/RT/拒绝数与规则。
- 已知边界：MQ 消费、自定义线程池、MySQL 与 Redis 客户端都没有纳入 trace。

## 二、主要功能描述

**触发与前置**

- 触发来源：浏览器请求页面与接口、网关转发、Feign 跨服务调用、`@Scheduled` 定时任务。
- 前置条件：模块引入 actuator、Micrometer OTel bridge、OTLP exporter，有 Feign 的模块额外引入 `feign-micrometer`。
- 模块配置采样概率与 OTLP HTTP endpoint，`spring.application.name` 作为 Jaeger 的 service name。
- Jaeger 已启动，OTLP HTTP 端口可达；服务能加载到公共配置与模块配置。

**做什么**

- 为 HTTP 请求创建 server span，记录方法、路径、状态码与耗时。
- 为 Feign 调用创建 client span，把 traceId 继续传给下游。
- 为 `@Scheduled` 方法创建 `tasks.scheduled.execution` span，异常时记录错误结果。
- 把 span 批量异步导出到 Jaeger，可按 service、operation、traceId 检索与对比耗时。
- 秒杀相关任务包括每日 3 点商品上架、每分钟建单与关单对账、每分钟限购对账。

**不做什么**

- 不修改业务数据，不发 MQ，不写业务表或缓存。
- 不创建自定义业务 span，不采集 SQL、Redis、RabbitMQ 子 span。
- 不做日志采集、metrics/logs 导出与 tail sampling。
- 不保证持久化，Jaeger 默认内存存储，容器重启后历史 trace 丢失。

**结果**

- 正常请求在 Jaeger 出现一条 trace，包含网关、seckill、product 等 span。
- 定时任务出现独立 trace；MQ 消费者内部若发 Feign，会成为新的根 trace。
- Jaeger 不可用或采样率为 0 时业务正常，只是没有新 trace。

**数据变化**

- HTTP 请求头：Feign 自动注入 `traceparent` 与 `tracestate`，用于下游关联 traceId。
- 网络与存储：span 批量发往 OTLP HTTP 入口，Jaeger 默认写入内存。
- 业务数据：MySQL、Redis、RabbitMQ 均不读不写。
- 日志：业务日志照常输出，tracing 本身不写业务日志。
- Nacos：只读配置与 Sentinel 规则。

**异常与边界**

- endpoint 端口或路径错误时导出失败，业务接口不受影响。
- 模块未引入依赖或配置未加载时，该段链路没有 server span。
- 采样率为 0 时不创建 span，Jaeger 看不到新数据。
- 直连秒杀子域的请求没有网关 span，不等于链路丢失。
- 多服务时钟不一致会导致 span 时间线错乱与耗时异常。
- OTLP 队列满或应用停机时，尾部 span 可能被丢弃。
- Sentinel 拦截的请求仍有 server span，但业务方法不执行，耗时很短。

## 三、执行顺序

1. 服务启动：读取 `spring.application.name`、采样概率与 OTLP endpoint，注册 tracing 与导出器。
2. 请求进入网关：自动创建 `gulimall-gateway` 的 HTTP server span。
3. `RtGlobalFilter#filter`：只记录 URI 与耗时日志，不创建自定义 span。
4. 网关转发：把当前 trace 上下文以 `traceparent` 注入下游请求头。
5. seckill 接收请求：读取 `traceparent`，创建同一 traceId 的 server span。
6. `SeckillController#skuInfo` / `SeckillOrderController#submit`：业务方法本身无埋点，耗时计入 server span。
7. Feign 调用发生：`feign-micrometer` 创建 client span，并继续传播 trace 上下文。
8. `ProductFeignClient#getSkuInfo`：调用 product，client span 记录目标服务、URL 模板与调用结果。
9. product 接收请求：创建 `gulimall-product` server span，执行 `SkuInfoController#info`。
10. `ItemController#loadSeckillSku`：product 反向调用 seckill，形成 product 到 seckill 的链路。
11. `OrderFeignClient` / `SeckillFeignClient`：order 与 seckill 互相调用时同样生成 client span 与下游 server span。
12. OTLP exporter：按批异步把 span 发往 Jaeger，不阻塞业务线程；停机时最后一批可能丢失。
13. `SeckillSkuScheduled#uploadSeckillSku`：每日 3 点创建独立任务 span。
14. `SeckillOrderReconcileTask#reconcile`：每分钟创建独立任务 span，异常时记录错误结果。
15. `SeckillOrderCreateListener#onCreate`：MQ 消费没有 consumer span，内部 Feign 调用成为新的根 trace。
16. `MyThreadConfig#requestAttributesTaskDecorator`：只复制 `RequestAttributes`，不传播 Micrometer 上下文，异步 Feign 断链。
17. Jaeger 检索：按 service、operation 或 traceId 查看 span 层级与各段耗时。
18. Sentinel Dashboard：按客户端端口 8719、8720、8721 查看机器与资源指标，与 Jaeger 互补。
